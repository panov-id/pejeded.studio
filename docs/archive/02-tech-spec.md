17 ноября 2026

Этот документ говорит, как строить приложение; что оно делает и почему, описано в плане продукта (`docs/01-product-plan.md`, «Сфера звука: технический план и дизайн»). ## 1. Границы первой версии

PEJEDED STUDIO — настольное приложение для одного пользователя. Название и надпись в кадре зашиты в код и не настраиваются. Интерфейс на английском.

| Входит | Не входит |
| --- | --- |
| Приём многоканального звука с любых USB-устройств; первое поддержанное устройство — MC-707 | Ручная расстановка источников на сфере |
| Пространство звука: живая объёмная карта «где сейчас какой звук», один вид «нити», плоские карты, палитры | Другие виды, фоны, разлетающиеся волны, следы и шлейфы |
| Камера: ручная и пролёт с привязкой к звуку | Скретч |
| Запись: аудио (общий микс) и видео со звуком | Запись отдельных каналов, вертикальное видео |
| 4 деки, микшер, предпрослушка, keylock, 4 hot cue, петли | Эффекты, сэмплер, драм-машина DJ-202 |
| Сетка битов, ведущая дека, SYNC по темпу и долям | Обработка микрофона в приложении |
| Передача темпа в DJ-202 и дальше в MC-707 | Библиотека с плейлистами и тегами |
| Список треков папки с поиском и сортировкой | Предварительный анализ всей папки |
| Эмуляторы DJ-202 и MC-707, тестовые сигналы | Перевод интерфейса, смена названия и логотипа |
| Вывод на второй экран, назначаемые клавиши и кнопки | Установщик, автообновление |
| Linux (Debian); затем macOS, старый и новый | Windows |

## 2. Окружение, зависимости, структура

Машина разработки: Debian, видеокарта AMD (драйвер Mesa), звук через PipeWire. Версия Debian не уточнялась: первым делом выполнить `cat /etc/os-release`, `glxinfo -B`, `pw-cli info 0` и записать результат в `docs/environment.md`.

| Часть | Решение | Замечание |
| --- | --- | --- |
| Язык | C++17 |  |
| Сборка | CMake, JUCE подключается как подмодуль git | Версию JUCE зафиксировать тегом. Проверить: минимальная версия macOS у выбранного тега и условия лицензии для личного использования |
| Звук, MIDI, окна, декодирование | JUCE (модули audio\_devices, audio\_formats, audio\_utils, dsp, gui\_basics, opengl) | На Linux вход в PipeWire через его JACK-слой; запасной путь ALSA. Проверить задержку обоих путей |
| Графика | OpenGL 3.3 core, шейдеры GLSL 330 | Никаких расширений выше 3.3: старый мак их не даст |
| Видео | Внешний процесс `ffmpeg`, кадры через pipe | Библиотеки FFmpeg не линкуются |

| Файлы настроек и данных | JSON средствами JUCE |  |
| Тесты | Catch2, запуск через `ctest` | Тестируются анализ, сетка битов, логика ведущей деки и SYNC, форматы файлов |

**Разработка в Docker.** Сборка и автотесты идут в контейнерах. Готовая программа запускается прямо на машине, без контейнера: так между ней и видеокартой, звуком и USB-устройствами нет посредника, задержка звука меньше, а на сцене надёжнее. Компилятор и библиотеки для сборки живут только в образе. Образ один, описан в `Dockerfile` и строится на той же версии Debian, что стоит на машине, чтобы собранная в нём программа запускалась на машине. Каталог проекта подключается в контейнер томом, поэтому исходники и папка `build/` остаются на диске машины. Процессы в контейнере работают от того же пользователя, что на машине, чтобы файлы не становились чужими.

В `compose.yaml` два сервиса на одном образе; обоим нужен только каталог проекта, без экрана, звука и устройств:

| Сервис | Зачем |
| --- | --- |
| `dev` | Сборка и любые команды |
| `test` | Все автотесты одной командой |

На саму машину ставятся Docker и то, что нужно программе для работы, а не для сборки: `ffmpeg` для видеозаписи и системные библиотеки звука и графики, которые на рабочем столе Debian обычно уже есть. Точный список составляется на этапе 1 и записывается в `docs/environment.md`; ставит его пользователь, без его согласия на машину ничего не ставится. Проверить на этапе 1: программа, собранная в контейнере, запускается на машине и видит видеокарту, звук и MIDI.

**Сборка под macOS.** Код один на обе системы, но собрать маковскую версию в Linux-контейнере нельзя, поэтому её собирает GitHub Actions на своих маках, начиная с этапа 1. При каждом изменении кода собирается программа в формате Universal (один файл для маков на Intel и на Apple Silicon), прогоняются те же автотесты, готовая программа выкладывается архивом для скачивания. Пользователю на маке ничего ставить и собирать не нужно: скачать, распаковать, запустить. Описание сборки лежит в `.github/workflows/macos.yml`.

- Репозиторий на GitHub открытый (решение пользователя). Поэтому в него не попадают треки, записи сетов, личные настройки, пароли и ключи; это закреплено в `.gitignore`.
- Программа не подписана Apple, поэтому первый запуск на маке разрешается вручную в настройках безопасности; пошаговая инструкция пишется в `docs/macos.md`.
- Проверить: какую минимальную версию macOS допускает выбранная версия JUCE; работает ли OpenGL 3.3 на версии macOS нового мака (Apple объявила OpenGL устаревшим); условия бесплатных маковских сборок для открытых репозиториев.
- На самом маке проверяется только то, что требует настоящей машины: картинка, звук, устройства (этап 9).

**Автотесты.** Проверка работы идёт автотестами в контейнере, одной командой `docker compose run --rm test`. Тесты двух видов:

- **Модульные** (Catch2): анализ звука (включая сухость и сигнал полосы), раскладка в куб, сетка битов, выбор ведущей деки, SYNC, разбор файлов паттерна и песни (включая сокращения, акценты и формулы), файлы настроек и данных трека.
- **Сквозные:** приложение запускается без экрана на эмуляторах MC-707 и DJ-202, со звуковым выходом-заглушкой и программной отрисовкой OpenGL (Mesa llvmpipe). Сценарий подаёт команды тем же путём, что контроллер (MIDI-сообщения эмулятора), и проверяет результат: уровни источников, положение тестовых сигналов в нарисованном кадре, содержимое записанных файлов, синхрон звука и картинки, темп на выходе, сведение дек под SYNC, отсутствие пропусков звуковых блоков.

Для сквозных тестов у приложения есть режим без окна, в котором время задаёт тест, а не часы: часовой прогон занимает минуты, результат одинаков при каждом запуске. Каждый критерий готовности из раздела 15, который можно проверить программой, закрывается автотестом, и этап не считается готовым, пока все тесты не проходят. Глазами и ушами пользователя проверяется только то, что программа оценить не может: красиво ли выглядит, хорошо ли звучит keylock, удобен ли джог; и всё, что касается настоящего железа (этап 8).

Команды сборки и проверки (сборка и тесты в контейнере, запуск на машине):

```text
docker compose build
docker compose run --rm dev cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
docker compose run --rm dev cmake --build build
docker compose run --rm test
./build/PejededStudio
```

## 3. Архитектура

Приложение состоит из слоёв, которые общаются только через очереди и снимки данных. Звуковые потоки никогда не ждут графику, диск или интерфейс.

```text
 MC-707 USB (вход, 20 кан.)          DJ-202 USB (выход 4 кан., MIDI)
        |                                  ^            ^
 [поток захвата]                   [поток вывода]   [поток MIDI]
        | кольцевые буферы                | Master/Phones  | события, подсветка, темп
        v                                  |            v
 [поток анализа] --снимок--> [рендер]   [DJ-движок] <-- [очередь команд]
        |                         |           ^            ^
        | микс                    | кадры     | треки      | действия
        v                         v           |            |
 [запись аудио]            [запись видео]  [рабочие потоки]  [интерфейс, клавиши]
                              -> ffmpeg     (загрузка, анализ трека)
```

| Поток | Что делает | Чего в нём нельзя |
| --- | --- | --- |
| Захват (колбэк устройства MC-707) | Копирует каналы в кольцевые буферы для анализа, записи и монитора | Выделять память, брать блокировки, писать в лог и на диск |
| Вывод (колбэк устройства Master) | Считает деки и микшер, отдаёт Master и Phones | То же |
| Анализ | Спектр по источникам, публикует `AnalysisFrame` | Ждать рендер |
| Рендер (OpenGL) | Рисует окно, второй экран и кадр для записи | Трогать звуковые данные напрямую |
| Запись аудио, запись видео | Пишут на диск и в pipe ffmpeg | Блокировать остальные потоки при медленном диске |
| MIDI | Принимает сообщения контроллера, шлёт подсветку и темп | Выполнять долгую работу |
| Рабочие потоки | Декодируют и анализируют треки |  |
| Интерфейс (message thread JUCE) | Экраны, настройки, клавиши |  |

Правила обмена:

- **Звук из захвата** идёт через кольцевые буферы «один писатель, один читатель»; на каждого читателя свой буфер. Переполнение считается и показывается в строке состояния, но писателя не останавливает.
- **Результат анализа** публикуется как «последнее значение»: рендер берёт самый свежий снимок без ожидания.
- **Команды в DJ-движок** (play, cue, питч, джог, EQ) идут через очередь команд без блокировок и применяются в начале звукового блока.
- **Состояние дек для экрана** (позиция, темп, ведущая) движок публикует тем же способом «последнее значение».
- **Загруженный трек** передаётся движку готовым неизменяемым объектом; старый освобождается вне звукового потока.

Ключевые интерфейсы (эскиз, имена можно уточнять, разделение обязанностей менять нельзя):

```cpp
// devices/: настоящее устройство и эмулятор реализуют одно и то же
struct IAudioInput {            // MC-707 или его эмулятор
  virtual int    numChannels() const = 0;
  virtual double sampleRate()  const = 0;
  virtual void   setCallback(IAudioInputCallback*) = 0;   // блоки float, не чередующиеся
  virtual DeviceState state() const = 0;                  // Absent, Opening, Running, Lost
};
struct IAudioOutput {           // DJ-202, звук ноутбука, HDMI
  virtual void setRenderer(IAudioRenderer*) = 0;          // render(out, numCh, numFrames)
};
struct IMidiPort {              // вход и выход MIDI
  virtual void send(const MidiMsg&) = 0;
  virtual void setCallback(IMidiCallback*) = 0;
};

// control/: всё приложение видит контроллер только так, без MIDI-кодов
struct ControlEvent { ControlId id; int side; float value; bool shift; };
struct IController {
  virtual void setListener(IControlListener*) = 0;        // ручки, кнопки, джоги
  virtual void setLed(LedId, int side, LedState) = 0;     // подсветка
  virtual void setTempo(double bpm) = 0;                  // темп для цепочки до MC-707
};

// analysis/: снимок, который читает рендер
constexpr int kBands = 32, kMaxSources = 12;
struct BandFrame   { float level, onset, pan, corr, dry, grain; };    // 0..1, 0..1, -1..1, -1..1
struct SourceFrame { BandFrame bands[kBands]; float rms, peak; bool active; };
struct AnalysisFrame {
  int64_t     sampleTime;                                  // часы захвата
  SourceFrame sources[kMaxSources];
  float       totalRms; bool beat; double bpm; double beatPhase;  // 0..1 внутри доли
};
```

## 4. Устройства и маршрутизация звука

У приложения два независимых звуковых тракта: приём с MC-707 (только для сферы, записи и монитора) и вывод дек. У них разные устройства и разные часы, и смешивать их напрямую нельзя.

**Схема на сцене:**

```text
 приложение --USB звук--> DJ-202 --Master, кабель--> MC-707 EXT IN
 приложение <--USB MIDI--> DJ-202 --MIDI OUT, кабель--> MC-707 MIDI IN
 наушники <-- DJ-202 Phones          микрофон --> DJ-202 MIC IN
 MC-707 MIX OUT --кабель--> пульт, зал
 MC-707 --USB, все каналы + MIDI clock--> приложение
```

**Входы: любое USB-устройство.** Слой устройств не привязан к MC-707. Источником может быть любое многоканальное звуковое устройство, которое видит система: грувбокс, звуковая карта, микшер. Для каждого устройства хранится профиль: имя, число каналов и карта каналов (какие пары образуют источники сферы и какая пара, если она есть, несёт общий микс). MC-707 — первый готовый профиль. Для незнакомого устройства профиль создаётся сам: каналы по порядку разбиваются на стереопары, общего микса нет; его можно поправить на экране Settings. Если у устройства нет пары общего микса, запись и монитор берут сумму его источников. Несколько устройств работают одновременно.

**Вход MC-707.** Ожидается 20 каналов. Карта каналов хранится в настройках и правится на экране Settings; значения по умолчанию — предположение, проверить на железе.

| Каналы (по умолчанию) | Поток | Как используется |
| --- | --- | --- |
| 1–2 | MIX | Аудиозапись, звук в видео, монитор, определение темпа по бочке. На сфере не рисуется, иначе всё задвоится |
| 3–18 | TRACK 1–8, по стереопаре | 8 источников сферы, у каждого свой цвет |
| 19–20 | EXT IN (деки и микрофон) | Девятый источник сферы, один цвет |

- Если устройство отдаёт только одну стереопару, сфера рисует её как единственный источник (режим «mix only»).
- Частота дискретизации входа берётся с устройства; анализ и запись работают на ней. Ожидается 48 кГц, проверить.
- Настройки на самом MC-707: включить MIDI Sync Out USB; задать Direct USB Mixout, чтобы уровень микса в USB не зависел от ручки VOLUME; режим USB Driver оставить тем, при котором Linux видит много каналов.

**Дополнительные входы.** Кроме MC-707 можно подключить любые другие звуковые устройства системы: в Settings выбираются устройство и его стереопары (или одиночные каналы как моно), и каждая становится ещё одним источником сферы со своим цветом, усилением и выключателем. Всего источников не больше 12. У каждого устройства свой поток захвата и свои кольцевые буферы; расхождение часов между устройствами для картинки не важно. В запись дополнительные входы не попадают: пишется только поток MIX с MC-707.

**Выходы дек.** Master и Phones назначаются независимо: устройство плюс пара каналов.

- Варианты в списке: DJ-202, динамики ноутбука, гнездо наушников, HDMI, любое другое устройство системы.
- По умолчанию на сцене: DJ-202, каналы 1–2 Master и 3–4 Phones (проверить на железе). DJ-202 работает на 48 кГц.
- Устройство Master задаёт часы DJ-движка. Если Phones назначен на другое устройство, его сигнал идёт через кольцевой буфер с подстройкой скорости (компенсация расхождения часов).
- Смена выхода происходит без перезапуска приложения; на время переключения допускается короткая тишина с плавным входом, без щелчка.
- Список устройств обновляется при подключении и отключении.

**Монитор.** Переключатель Monitor подмешивает поток MIX с MC-707 в выход Master приложения. По умолчанию выключен. Путь идёт через кольцевой буфер с подстройкой скорости. При включении показывать предупреждение, если Master назначен на DJ-202: на сценической схеме это замкнёт петлю (микс 707 вернётся в его же вход).

**MIDI-порты.**

| Порт | Направление | Зачем |
| --- | --- | --- |
| DJ-202 | вход | Ручки, кнопки, джоги, пэды |
| DJ-202 | выход | Подсветка, темп для цепочки до MC-707 |
| MC-707 | вход | MIDI clock как запасной источник темпа для камеры |
| Direct clock out (любой порт, по умолчанию не задан) | выход | Запасной путь: приложение само шлёт MIDI clock в MC-707 через USB-MIDI-адаптер, если DJ-202 темп не принимает |

**Потеря устройства.** Каждое устройство живёт по схеме Absent → Opening → Running → Lost → Opening. В состоянии Lost приложение раз в секунду пробует открыть устройство заново и показывает предупреждение в строке состояния. Потеря MC-707 останавливает только сферу и запись; потеря устройства, на которое назначен Master, ставит деки на паузу с сохранением позиций и после возврата ждёт команды пользователя; потеря только MIDI-связи с контроллером деки не останавливает, управление остаётся с экрана.

## 5. Анализ звука

Место звука в кубе вычисляется только из звука: панорама даёт место влево-вправо, частота даёт высоту, сухость звука даёт расстояние (сухой близко, размытый далеко), фаза между каналами даёт ширину формы. Ручной расстановки нет. Слова «сфера» и «пространство звука» в этом документе значат одно и то же: куб, в центре которого стоит слушатель (решение пользователя: куб вместо сферы).

**Параметры разбора** (начальные значения, подбираются на глаз):

| Параметр | Значение |
| --- | --- |
| Окно и шаг | 2048 и 512 отсчётов, окно Ханна (при 48 кГц до 94 снимков в секунду; сколько берётся на деле, задаёт Rate, см. ниже) |
| Полосы | 32, логарифмически от 30 Гц до 16 кГц |
| Источник | Стереопара; до 12 источников, на сцене 9 (8 треков и EXT IN) |
| Порог активности источника | RMS выше −60 dBFS |

**На каждую полосу каждого источника** по бинам спектра k этой полосы:

```text
PL = sum |L[k]|^2          PR = sum |R[k]|^2          C = sum Re( L[k] * conj(R[k]) )

pan   = (PR - PL) / (PR + PL + eps)                 -1 слева ... +1 справа
corr  = C / sqrt(PL * PR + eps)                     +1 в фазе ... -1 в противофазе
        если один канал тише другого больше чем на 40 дБ, corr = 1
level = clamp( (10*log10(PL + PR) + 70) / 60, 0, 1 ) * gain источника
onset = положительный прирост энергии полосы к её скользящему среднему, 0..1; спад за 0,1 с

attack = самый резкий недавний скачок громкости полосы, 0..1:
         attack = max( attack * exp(-dt / 2 с), clamp(2.5 * (level_новый - level_прежний), 0, 1) )
dry    = сухость полосы, 0 размытый .. 1 сухой:
         цель = 0.6 * attack + 0.4 * |corr|
         dry += (цель - dry) * min(1, 6 * dt)       обновляется только у полос громче порога; начальное значение 0.5

grain = шумовой характер полосы, 0 тон .. 1 шум. Для полосы из n >= 6 бинов:
        crest = max(|L[k]|^2 + |R[k]|^2) / ((PL + PR) / n)
        grain = 1 - clamp((crest / n - 0.12) / 0.3, 0, 1)
        для полос уже 6 бинов grain = 0
        в картинке сейчас не используется: шум виден по самому сигналу полосы
```

**Ручка Decay** (затухание) задаёт, как быстро форма пропадает после того, как звук замолчал. Картинка показывает только то, что звучит сейчас: искусственного продления, следов и шлейфов нет (решение пользователя; прежняя ручка Inertia отменена).

| Величина | Значение |
| --- | --- |
| Нарастание level | 6 мс, не настраивается |
| Спад level | Decay: от 20 до 600 мс, по умолчанию 90 мс |
| pan и corr | Следуют за звуком за один-три снимка; обновляются только у полос громче порога |

onset не сглаживается; он нужен только пролёту камеры (модулятор Kick). Частота съёма (настройка Rate в панели Look): сколько раз в секунду анализ отдаёт новый снимок и пересчитывается поле плотности. Варианты 60, 30, 20, 15 и 10 раз в секунду, по умолчанию 30 (решение пользователя: снимать реже и дать выбор). Между снимками формы стоят на месте, а течение нитей и камера идут каждый кадр, поэтому картинка не дёргается. Окно разбора 2048 отсчётов от частоты съёма не зависит; нарастание и спад level считаются по настоящему времени между снимками.

**Сухость (dry): откуда берётся расстояние.** Фаза между каналами почти не даёт глубины: у обычной музыки почти всё в фазе, и все звуки оказывались в одном слое у передней стенки (пользователь: «не чувствуется объём», «2D, прилепленное к 3D»). Поэтому расстояние берётся из того, сухой звук или размытый (выбор пользователя из трёх вариантов: громкость, сухость, оставить фазу). Сухой чёткий звук с резкими атаками стоит близко, размытый без атак далеко. Оценка грубая и собрана из двух измерений: был ли у полосы резкий скачок громкости за последние пару секунд (attack) и насколько каналы совпадают по фазе (|corr|); формула выше. Известная ошибка: ровный сухой синтезатор без атак уезжает далеко, как будто он с реверберацией; настоящую реверберацию от просто длинной ноты так не отличить. Пользователь об этом предупреждён.

**Раскладка в куб** (модуль `visual/SpaceMapping`). Пространство звука — куб. Слушатель в центре, в точке (0, 0, 0); ось X вправо (панорама), Y вверх (частота), Z назад (перёд — это −Z). Оси прямые, ничего не заворачивается дугой вокруг слушателя. Единица длины условная: звук лежит в пределах ±1,25.

Каждая полоса каждого источника даёт одну объёмную форму:

| Что | Формула | Смысл |
| --- | --- | --- |
| Высота центра | y = −0,85 + 1,7 × b / 31 | Частота: бас внизу, верха наверху |
| Место влево-вправо | x = pan × 0,95 | Панорама |
| Расстояние | z = −(0,55 + 0,7 × (1 − dry)) | Сухой близко (z около −0,55), размытый далеко (z около −1,25) |
| Противофаза | если corr меньше −0,3, знак z меняется на плюс | Звук в явной противофазе стоит сзади, на том же расстоянии |
| Ширина | σx = 0,16 + 0,45 × (1 − \|corr\|) | Звук в фазе узкий, широкий стереозвук растянут по панораме |
| Глубина и высота формы | σz = 0,17; σy = 0,05 | Постоянные |
| Вес | корень из (0,16 / σx) | Широкая форма не становится ярче узкой |

Плотность формы = level^2,4 × 1,3 × вес × (1 + 1,3 × onset). Полоса с level меньше 0,1 пропускается. Форма — гауссов сгусток с этими центром и размерами.

Один источник (дорожка) даёт формы в разных местах сразу: у каждой полосы свои pan, corr и dry. Так барабанная дорожка показывает бочку внизу близко, хэт наверху сбоку, клэп широко.

Прежняя раскладка отменена: глубина по фазе (в фазе спереди, противофаза сзади) и два боковых сгустка для широких звуков.

**Сигнал полосы** (модуль `analysis/BandSignal`). Нити на экране — это настоящие сигналы полос, поэтому для каждой полосы каждого источника при каждом съёме восстанавливается кусок её сигнала прямо из её же бинов спектра, без отдельных фильтров:

```text
вход: спектры L[k], R[k] текущего окна (2048 отсчётов, окно Ханна), бины k полосы
M[k] = L[k] + R[k]    общее в каналах (mid)        S[k] = L[k] - R[k]    разница каналов (side)

km    = бин полосы с наибольшей энергией |M|^2 + |S|^2
P     = 2048 / km                                 период в отсчётах
span  = min(4 * P, 900)                           сколько отсчётов показать: около 4 периодов, у баса меньше
start = 512 + d                                   d от 0 до P: сдвиг до ближайшего перехода главной составляющей через ноль вверх
                                                  (как запуск развёртки на осциллографе); d не больше 1024 - span
для j = 0..63:   n = start + j * span / 64
  mid[j]   = sum Re( M[k] * e^(i * 2*pi*k*n / 2048) )     сам сигнал
  quad[j]  = sum Im( M[k] * e^(i * 2*pi*k*n / 2048) )     тот же сигнал со сдвигом на четверть периода
  side[j]  = sum Re( S[k] * e^(i * 2*pi*k*n / 2048) )
  все три делятся на окно Ханна в точке n (не меньше 0,3), чтобы снять его огибающую
все три нормируются к общему пику и умножаются на min(1, 1,25 * level)
```

Результат лежит в текстуре 64 × (32 × число источников): в строке полосы три канала mid, side, quad в диапазоне −1..1. Полоса тише 0,1 не пересчитывается и держит прежнюю строку (её форма всё равно гаснет). Экспонента считается поворотом комплексного числа на постоянный угол от отсчёта к отсчёту, без вызова синуса на каждый отсчёт. В прототипе расчёт для пяти дорожек занимает 4–5 мс на съём.

Ограничения способа (пользователю названы): в окно анализа попадает меньше одного периода самых низких частот, поэтому нити баса почти прямые; одна низкая нота размазывается на несколько соседних полос, и вместо одной нити видно несколько похожих. Проверить на этапе 2: более длинное окно для нижних полос.

**Поле плотности.** Каждый съём все формы всех включённых источников складываются в трёхмерную сетку 56 × 40 × 56 (X × Y × Z), которая покрывает объём ±1,45 по X и Z и ±1,1 по Y. Плотность копится и хранится отдельно по каждому источнику: у источника свой канал плотности, плюс один общий канал с наибольшей плотностью в ячейке (по нему луч пропускает пустоту). На 12 источников это три RGBA-текстуры плотности и одна одноканальная. Плотность пишется в 8 бит с множителем 0,6, шейдер делит обратно: так громкие звуки не упираются в потолок и видно, кто из двух сильнее. Цвет в сетке не хранится: его даёт номер канала, поэтому на границе двух источников цвета не грязнятся. Сетка загружается в 3D-текстуры с линейной фильтрацией; её читают рендер и «тяга к звуку» камеры. Размер сетки начальный, зависит от ступени качества (раздел 6). Кроме сетки рендеру нужна маленькая текстура 32 × число источников: у каждой полосы её level, onset и центр формы (x, z).

**Темп по звуку.** По низким полосам потока MIX ищутся удары и оценивается BPM. Это запасной источник темпа для камеры (раздел 9).

**Ожидаемое поведение на тестовых сигналах** (оно же проверяется модульными тестами):

| Сигнал | Что должно получиться |
| --- | --- |
| Ровный тон 1 кГц, одинаковый в обоих каналах | Одна узкая форма по центру (x = 0) на средней высоте, спереди, далеко: dry сходится к 0,4, z около −0,97 |
| Тот же тон, панорама идёт слева направо | Форма едет по прямой вдоль X от −0,95 до +0,95 на том же расстоянии |
| Тон, частота идёт от 40 Гц до 12 кГц | Форма поднимается снизу вверх |
| Тон, правый канал в противофазе | Форма сзади по центру: z около +0,97 |
| Независимый шум в каналах | Широкая форма (σx около 0,6) на всю высоту, у дальней стенки: dry сходится к 0, z около −1,25 |
| Короткие удары того же тона дважды в секунду, одинаковые в каналах | Форма заметно ближе, чем у ровного тона: dry больше 0,7, z ближе −0,8 |
| Тишина | Источник неактивен, форм нет |
| Сигнал полосы для ровного тона 1 кГц | mid — синусоида с 4 периодами на 64 отсчёта, начинается с перехода через ноль вверх; quad — она же со сдвигом на четверть периода; side равен нулю |

## 6. Визуал

Сцена каждый кадр рисуется один раз в внеэкранный буфер («программный кадр») в разрешении записи. Этот кадр уходит в три места: окно зрителей, запись видео и окно ноутбука (целиком или миниатюрой). Панели интерфейса рисуются поверх только в окне ноутбука.

**Пространство звука: что на экране.** Экран в реальном времени показывает, где сейчас какой звук. Это рабочий инструмент: по картинке пользователь пишет музыку и собирает панорамный звук, поэтому точность и читаемость важнее украшений. Правила ниже подтверждены пользователем на прототипе и заменяют все прежние режимы (Particles, Membrane, Lines, Rings) и фоны (Nebula, Stardust, Grid, Echo):

- Пространство звука — куб, а не сфера (решение пользователя). Оси прямые: влево-вправо — панорама, вверх-вниз — частота, ближе-дальше — сухой или размытый звук. Слушатель в центре, камера внутри (раздел 5).
- Звук виден не точкой, а объёмной формой такого размера, сколько он занимает по панораме и по частотам. Форма по высоте — это АЧХ звука: она занимает те частоты, которые в нём есть, и плотнее там, где частота громче. Ширина формы — фаза: широкий стереозвук шире.
- Форма заполнена пучком нитей, и каждая нить — настоящий сигнал своей полосы частот. Случайного и придуманного узора в картинке нет (требование пользователя): один и тот же звук всегда даёт одну и ту же картинку.
- Только настоящее время: звук есть — форма есть, замолчал — форма пропала за время Decay. Разлетающихся волн, следов, шлейфов и эха нет.
- Цвет — источник (дорожка), с подкраской по высоте. Плотность и яркость — громкость. Белый — только спор двух звуков за одно место.
- Фон чёрный. Вид один; переключения видов нет. Картинка чистая: без песка и дымки между нитями.
- Камера не выходит за пределы куба ни вручную, ни в пролёте: |x| и |z| не больше 1,3, |y| не больше 0,95. Угол обзора широкий, начальное значение 84°. Камера может пролетать сквозь формы.

**Вид: пучок нитей из настоящих сигналов.** Место и размер звука в кубе даёт поле плотности (раздел 5). Внутри форма заполнена прямыми рядами нитей: нити идут вдоль оси X (панорама), ряды стоят по высоте (один на полосу частот) и по глубине (шаг 0,09). Каждую нить отклоняет сигнал её полосы (раздел 5, «Сигнал полосы»): по высоте — сам сигнал, по глубине — тот же сигнал со сдвигом на четверть периода и разница каналов. Поэтому тон выглядит спиралью, а не волной на листе, шум — ломаной нитью, широкий звук расходится в глубину сильнее моно. Соседние по глубине ряды показывают соседние куски того же сигнала, поэтому они не копии друг друга.

Объём рисуется трассировкой лучей фрагментным шейдером. Луч идёт в два уровня: 56 крупных шагов через куб, и только там, где общий канал плотности больше 0,004, крупный шаг делится на 4 мелких (dt = четверть крупного). Начало мелких шагов сдвинуто на долю шага упорядоченным шумом по координатам пикселя (interleaved gradient noise), который каждый кадр сдвигается по порядку; это сглаживание, на форму нитей оно не влияет, и это единственное в кадре, что берётся не из звука и не из постоянных правил раскладки. Толщина нити не бывает меньше того, что луч успевает поймать (w в формуле), а яркость при этом падает во столько же раз: тонкая нить вдали гаснет, а не искрит. На каждом мелком шаге в точке p для каждого источника с плотностью больше 0,006:

```text
h   = clamp((p.y + 0.85) / 1.7, 0, 1)          высота = частота: 0 бас, 1 верха
c0  = round(h * 31)                            ближайшая полоса
w   = max(0.0045, dt * 0.55)                   толщина нити, не тоньше шага луча
acc = 0
для полос c = c0 - 1, c0, c0 + 1, у которых level >= 0.1:
  (x0, z0)    = центр формы этой полосы (раздел 5)
  al          = p.x - x0                       вдоль нити: панорама
  dp          = p.z - z0                       поперёк: глубина
  kr          = round(dp / 0.09)               номер ряда нитей по глубине
  u           = al / 1.2 + 0.5 + kr * 0.29     место в сигнале полосы; за краями 0..1 сигнал зеркально отражается
  (m, sd, q)  = mid, side, quad сигнала полосы в точке u, -1..1
  d1          = p.y - y(c) - 0.05 * m                              отклонение по высоте: сам сигнал
  d2          = dp - kr * 0.09 - 0.028 * (0.8 * q + 0.6 * sd)      отклонение по глубине
  acc        += exp(-(d1^2 + d2^2) / w^2) * smoothstep(0.1, 0.3, level)
t   = acc * (0.0045 / w) * 7 * smoothstep(0.02, 0.3, density) * (0.35 + density)

спор двух звуков: m1 и m2 — две наибольшие плотности источников в точке
clash = smoothstep(0.5, 0.9, m2 / m1) * smoothstep(0.04, 0.22, m2)
d     = t * gain * dt * 9 * (1 + 1.2 * clash)

цвет:
tint(c, h) = поворот оттенка c на (h - 0.5) * 0.3 радиан вокруг серой оси, затем mix(c * 0.8, mix(c, white, 0.28), h)
c     = mix(tint(source_color, h), white, 0.92 * clash)
near  = 0.22 + 0.78 / (1 + dist^2 * 0.7)       dist: расстояние от камеры до точки

color += (1 - a) * c * d * 1.6 * near          по всем источникам в точке
a     += (1 - a) * min(1, сумма d)
после цикла: L = max(color.r, color.g, color.b);  color *= (1 - exp(-1.9 * L)) / L
```

**Что в картинке от чего зависит:**

| Что в звуке | Что на экране |
| --- | --- |
| Баланс левого и правого канала в полосе (pan) | Место формы влево-вправо |
| Частота полосы | Высота; вертикальная форма звука — его АЧХ |
| Сухость (dry): резкие атаки и совпадение каналов | Расстояние: сухой близко, размытый далеко |
| Фаза между каналами (corr) | Ширина формы; явная противофаза — форма сзади |
| Громкость полосы (level) | Плотность и яркость нитей, размах их отклонения; тише порога — пусто |
| Резкая атака (onset) | Форма коротко сгущается: плотность умножается на (1 + 1,3 × onset) |
| Сам сигнал полосы | Форма каждой нити: тон — ровная спираль, биения и переливы — меняющаяся, шум — ломаная |
| Разница каналов в полосе (side) | Дополнительное отклонение нити в глубину |
| Два звука в одном месте, почти равные по силе | Нити обоих белеют |
| Звук замолчал | Форма гаснет за время Decay |

От звука не зависят: цвет дорожки (это её номер), постоянные правила раскладки (какая частота на какой высоте, шаг рядов, размах отклонения, сколько сигнала помещается в нить) и ручка Density. Случайных чисел в отображении нет.

Условности, о которых пользователь знает: размах отклонения нити меньше шага между рядами (иначе пришлось бы проверять втрое больше рядов на каждый шаг луча); куски сигнала на соседних рядах через один идут в обратную сторону, чтобы на стыке не было излома; ровная чистая нота стоит неподвижной спиралью, потому что её сигнал не меняется и снимается всегда с одного места периода.

**Два звука в одном месте: спор (выбор пользователя из четырёх показанных способов).** Если две дорожки занимают одно место на одних частотах (например бочка и бас), это правда о миксе, которую нужно показать. Пока один звук заметно сильнее другого, оба рисуются своими нитями и своими цветами, цвета в третий не смешиваются. Там, где второй по силе звук почти равен первому (clash в формуле: начинается при отношении плотностей 0,5, полный при 0,9), нити обоих белеют и горят ярче. Порог поднят с 0,2–0,7 после проверки на настоящем звуке: при прежнем белело почти всё. Белое на экране значит одно: здесь два звука спорят за место, их надо развести по частоте, панораме или времени. Отвергнутые способы: просто рядом без подсказки; громкий гасит тихого; яркость по фазе между дорожками.

**Подкраска по высоте (просьба пользователя).** Цвет дорожки остаётся её цветом, но внизу он глубже и темнее (× 0,8), наверху светлее (на 28 % к белому): по одной дорожке видно, где её низ и где верх. Сдвиг оттенка оставлен едва заметным (±0,15 радиана): при большем сдвиге одна дорожка становилась похожа по цвету на другую. Силу подкраски выбрал разработчик, пользователю показано.

**Глубина для глаза.** Дальние нити темнее ближних (near в формуле), ближние крупнее за счёт перспективы. Цвет после накопления приводится к экрану по самой яркой составляющей (последняя строка формулы), а не по каждой отдельно: насыщенный цвет дорожки не выгорает в белый, белый остаётся только знаком спора.

**Как пришли к этому виду** (чтобы не повторять отвергнутое):

| Вариант | Почему отвергнут |
| --- | --- |
| Точки, частицы, кольца, столбики анализатора, туманности | Не показывают, где какой звук, или некрасивы |
| Нити по готовому узору из шума, который звук только гнёт и двигает | Узор не из звука; на ровном звуке нити стояли |
| Одна нить на полосу с нарисованной синусоидой по громкости | Волны ненастоящие; стопка линий выглядит графиком |
| Одна нить на полосу с настоящим сигналом, дугой вокруг слушателя | Плоско: одна линия объёма не заполняет; тормозило |
| Глубина по фазе, звук завёрнут в сферу | Почти всё в одном слое, объёма нет |

Числа взяты из прототипа и подбираются на глаз. Ручка Density (gain, от 0,2 до 3, по умолчанию 1) делает нити ярче или бледнее. Эталон вида и раскладки — веб-прототип, который пользователь посмотрел и принял («ща норм»); его исходник лежит в `docs/prototype/sound-space.html`. Приложение должно выглядеть не хуже него; любое изменение вида сначала показывается пользователю, на настоящем звуке, а не на искусственных данных. В прототипе для этого есть автозапуск демо: адрес с `#auto` и необязательными `p=`, `y=` (наклон и поворот взгляда), `cx=`, `cy=`, `cz=` (место камеры).

Чего разработчик не проверил в прототипе: движение (смотрел только отдельные кадры с настоящего звука демо), скорость на видеокарте пользователя, работу на треках пользователя.

**Ориентиры** (включаются и выключаются, по умолчанию включены): каркас куба — квадрат пола и квадрат верха со стороной 2,5 (от −1,25 до 1,25), крест на полу с подписями front, back, left, right; по четырём вертикальным рёбрам шкалы частот с делениями 50 Hz, 200 Hz, 1 kHz, 5 kHz, 12 kHz. В программный кадр для зрителей и записи ориентиры попадают, только если включены.

**Плоские карты** (открываются по нажатию, по умолчанию спрятаны): Top — панорама против расстояния; Front — панорама против частот. Рисуются из тех же форм теми же цветами, поверх кадра только в окне ноутбука. В окно зрителей и в запись не попадают.

**Палитры.** Четыре набора в `resources/palettes.json`: Neon, Mono, Warm, Cold. В каждом 9 цветов (8 треков и EXT IN). Цвет любого источника можно переопределить; переопределения хранятся в настройках. У источника также есть усиление для картинки и выключатель; на звук они не влияют.

**Ручная камера.** Перетаскивание мышью поворачивает взгляд, колесо двигает камеру вперёд и назад по направлению взгляда. Ходить по кубу можно с клавиатуры (замечание пользователя: без этого камеру не сдвинуть как надо, а объём на чёрном фоне виден в основном в движении): стрелки — вперёд, назад, влево, вправо; Page Up и Page Down — вверх и вниз; Shift — быстрее. Скорость 0,7 единицы в секунду, с Shift 1,6. В прототипе те же движения висят ещё и на W A S D, Q и E; в приложении эти буквы не используются, потому что S занята панелью Sources (решение разработчика, с пользователем не обсуждалось). Камера не выходит за пределы куба. Вид по умолчанию и по клавише сброса: из центра, взгляд вперёд.

**Пролёт.** Камера идёт по гладкому сплайну через случайные точки внутри пространства звука (в пределах объёма) и плавно меняет направление взгляда. Четыре модулятора включаются по отдельности, у каждого ручка силы 0–1:

| Модулятор | Действие |
| --- | --- |
| Speed | Скорость движения по сплайну растёт с общей громкостью |
| Kick | Onset в низких полосах толкает камеру вбок и коротко расширяет угол обзора; сильный удар меняет направление |
| Attract | Следующие точки сплайна и точка взгляда смещаются к самой плотной зоне поля плотности |
| Tempo | Новый участок траектории начинается ровно раз в 4, 8 или 16 тактов по шине темпа |

Угловая скорость камеры ограничена сверху, чтобы картинка оставалась читаемой на большом экране.

**Надпись.** Текст `PEJEDED STUDIO` зашит в код. В настройках: включена или нет, угол кадра, размер. Рисуется в программный кадр, поэтому попадает и зрителям, и в запись.

**Второй экран.** Окно без рамки и курсора на весь выбранный дисплей, показывает программный кадр. Включается и выключается на ходу. На ноутбуке при этом остаётся главное окно со слоями (раздел 12); зрители видят только сферу:

- **Нижняя панель открыта:** на ноутбуке деки поверх сферы, зрители видят сферу целиком; камера в пролёте или стоит.
- **Нижняя панель закрыта:** на ноутбуке та же сфера, что у зрителей; камерой можно управлять мышью, зрители видят поворот.

**Качество.** Три ступени, цель 60 к/с:

| Ступень | Сетка плотности | Шагов на луч: крупных × мелких | Разрешение трассировки |
| --- | --- | --- | --- |
| Low | 40 × 28 × 40 | 40 × 3 | половина кадра |
| Medium | 56 × 40 × 56 | 56 × 4 | три четверти кадра |
| High | 72 × 52 × 72 | 72 × 6 | полный кадр |

Если кадр дольше бюджета две секунды подряд, ступень понижается сама и об этом пишется в строке состояния; сама она не повышается. Числа в таблице начальные, подбираются на видеокарте AMD машины разработки.

## 7. Запись

Запись взводится заранее, стартует сама с первым звуком и захватывает 2 секунды до него; останавливается кнопкой. Режимов два: Audio и Video + Audio.

**Состояния:** Idle → Armed → Recording → Finalizing → Idle.

| Параметр | Значение по умолчанию | Настраивается |
| --- | --- | --- |
| Источник звука | Поток MIX с MC-707 | нет |
| Порог автостарта | MIX громче −50 dBFS дольше 50 мс | да |
| Предзапись | 2 с | да |
| Аудио | WAV, 24 бита, частота устройства | WAV или FLAC |
| Видео | MP4, H.264, 1920×1080, 60 к/с | разрешение, к/с, качество |
| Имя файла | `{date}_{time}_{set}` | шаблон и название сета |
| Папка | задаётся пользователем | да |

**Аудио.** Поток записи читает свой кольцевой буфер MIX и пишет файл. В состоянии Armed буфер хранит последние 2 с; при срабатывании порога они идут в начало файла. Заголовок WAV обновляется каждые 10 с, чтобы после сбоя файл открывался.

**Видео.**

1. Программный кадр читается из видеопамяти асинхронно (два буфера PBO по очереди), чтобы рендер не ждал.
2. Кадры идут в очередь ограниченной длины, поток видеозаписи пишет их в stdin процесса `ffmpeg` как сырое видео.
3. Во время записи ffmpeg пишет контейнер MKV (переживает обрыв), звук параллельно пишется в WAV.
4. По кнопке Stop файлы склеиваются в MP4 без перекодирования видео, звук кодируется в AAC 320 кбит/с; исходный WAV остаётся рядом.
5. Предзапись в видеорежиме: кодирование идёт с момента взвода, а при склейке всё, что раньше «старт минус 2 с», отрезается по ближайшему ключевому кадру (ключевой кадр раз в секунду). Если взвод висит без звука дольше 10 минут, временный файл начинается заново.

Начальная команда кодировщика (параметры подобрать на машине, аппаратное кодирование на AMD рассмотреть позже):

```text
ffmpeg -f rawvideo -pix_fmt rgba -s 1920x1080 -r 60 -i - \
       -vf vflip -c:v libx264 -preset veryfast -crf 18 -g 60 -pix_fmt yuv420p out.mkv
```

**Синхрон звука и картинки.** Часы видео — счётчик отсчётов захвата. Поток видеозаписи отдаёт кодировщику ровно один кадр на каждую 1/60 с звукового времени: если свежего кадра нет, повторяет предыдущий; если кадров больше, лишние отбрасывает. Длительность видео и звука совпадает при любой длине сета.

**Правила надёжности:**

- Очередь кадров переполнена (кодировщик не успевает): кадр отбрасывается, счётчик пропусков виден в строке состояния. Звук и рендер не тормозят.
- Процесс ffmpeg упал: видеозапись останавливается с сообщением, аудиозапись продолжается.
- Приложение упало: на диске остаются MKV и WAV; при следующем запуске предлагается их склеить.
- Перед взводом проверяется наличие `ffmpeg` и свободное место; меньше 5 ГБ даёт предупреждение.
- Потеря MC-707 во время записи: в файл идёт тишина, запись не обрывается, после возврата устройства звук продолжается.

## 8. DJ-движок

Четыре деки играют независимо; контроллер в каждый момент управляет двумя из них. Левая сторона DJ-202 переключается между деками 1 и 3, правая между 2 и 4 (кнопки DECK). Дека, ушедшая из фокуса, продолжает играть с последними значениями ручек.

**Загрузка трека** (рабочий поток):

1. Файл декодируется целиком в память и приводится к частоте движка (48 кГц, стерео). После этого трек уже можно играть.
2. Если рядом лежит файл данных и размер с датой трека совпадают, BPM, сетка и метки берутся из него.
3. Иначе запускается анализ: BPM, сетка битов, вейвформа. До его окончания SYNC и петли на этой деке недоступны, кнопки приглушены.
4. Результат записывается в файл данных рядом с треком.

Форматы: MP3, FLAC, WAV, AIFF. Проверить: встроенный в JUCE декодер MP3 по умолчанию может быть выключен; если так, MP3 декодируется отдельной маленькой библиотекой или через процесс `ffmpeg`. Десятиминутный трек занимает в памяти около 230 МБ, четыре деки — до 1 ГБ.

**Дека.**

| Функция | Поведение |
| --- | --- |
| Play/Pause | Пуск и пауза с фейдом 5 мс, без щелчка |
| Cue | На паузе ставит точку cue в текущей позиции; при игре возвращает к точке и ставит паузу; удержание на точке играет, пока кнопка нажата (как на CDJ; подтверждено пользователем) |
| Питч | Фейдер, диапазон ±8 % |
| Keylock | Включён по умолчанию: темп меняется растяжением без сдвига тона. Выключен: передискретизация, тон идёт за темпом |
| Джог | При игре: временное ускорение или замедление, пропорциональное скорости вращения (подтяжка). На паузе: перемотка. Касание верха джога не отличается от бокового, скретча нет |
| Hot cue (верхний ряд, 4 пэда) | Пустой пэд ставит метку в текущей позиции (с привязкой к ближайшей доле, если есть сетка); занятый пэд прыгает к метке; SHIFT + пэд удаляет |
| Петли (нижний ряд, 4 пэда) | 1, 2, 4, 8 долей от ближайшей доли; повторное нажатие выходит из петли, другой пэд меняет длину. Без сетки недоступны |
| Конец трека | За 30 с до конца панель деки и кнопка Play на контроллере мигают; в конце дека останавливается |
| Защита LOAD | Загрузка отклоняется, если дека играет и слышна в Master; кнопка коротко мигает |

«Слышна в Master» значит: дека играет, фейдер канала выше нуля и кроссфейдер не уведён полностью в противоположную сторону. Это же определение использует выбор ведущей деки.

**Микшер.** Цепочка канала: trim → EQ → фильтр → фейдер → кроссфейдер → Master. Числа ниже начальные.

| Блок | Параметры |
| --- | --- |
| Trim | от −12 до +12 дБ |
| EQ | Три полосы с разделом около 250 Гц и 2,5 кГц; каждая от полного глушения до +6 дБ |
| Фильтр | Одна ручка: в центре выключен, влево срез верхов, вправо срез низов |
| Фейдер канала | от тишины до 0 дБ |
| Кроссфейдер | Деки 1 и 3 на стороне A, 2 и 4 на стороне B; кривая плавная |
| Master | Уровень и мягкий ограничитель на выходе |
| Предпрослушка | Кнопка CUE канала шлёт сигнал до фейдера в шину cue; ручка баланса cue/master; уровень Phones |

Мягкий подхват: после смены деки кнопкой DECK ручка или фейдер начинают действовать только после того, как прошли через сохранённое значение этой деки. То же правило действует для питч-фейдера после выключения SYNC.

**Вейвформы.**

- При анализе считаются три огибающие: бас (до 200 Гц), середина (200 Гц – 2 кГц), верха (выше 2 кГц). Каждая полоса рисуется своим цветом; цвета подбираются при вёрстке и не совпадают с цветами источников сферы.
- Бегущая вейвформа: вертикальная метка «сейчас» общая для всех дек. Масштаб по горизонтали в секундах звучания, то есть с учётом текущей скорости деки: у дек с одинаковым темпом удары визуально идут с одинаковым шагом. Видимое окно 8 с, меняется колесом.
- Поверх рисуются сетка битов (сильная доля выделена), метки hot cue, точка cue, границы петли.
- Две деки в фокусе контроллера нарисованы крупно, две остальные узкими полосками.
- Обзорная полоска всего трека с позицией на панели каждой деки; щелчок по ней перематывает (только на паузе или если дека не слышна в Master).

**Файл данных рядом с треком.** Имя: имя трека плюс `.pjd.json` (для `song.mp3` это `song.mp3.pjd.json`). Если папка закрыта от записи, файл кладётся в кэш приложения и показывается предупреждение.

```json
{
  "version": 1,
  "file": { "size": 9482113, "mtime": 1763380000 },
  "durationSec": 372.41,
  "bpm": 126.0,
  "grid": { "firstBeatSec": 0.213, "bpm": 126.0, "beatsPerBar": 4, "edited": false, "steady": true },
  "cueSec": 0.213,
  "hotcues": [ 0.213, 30.689, null, null ]
}
```

- `steady: false` отмечает трек с плавающим темпом: сетка ненадёжна, SYNC держит только темп.
- Правки сетки (сдвиг, удвоение, деление пополам, набивание) ставят `edited: true`; повторный анализ такую сетку не перезаписывает.
- Вейвформа в этот файл не пишется: она лежит в кэше приложения и при отсутствии пересчитывается.

**Список треков.**

- Показывает звуковые файлы выбранной папки и её подпапок. Колонки: Title (из тегов или имя файла), BPM, Length.
- BPM читается из файлов данных; у треков, которые ещё не загружались в деку, колонка пустая. Фонового анализа папки нет.
- Поле поиска фильтрует по подстроке названия; сортировка щелчком по заголовку колонки.
- Энкодер DJ-202 двигает выделение; LOAD слева или справа грузит выделенный трек в деку, находящуюся в фокусе этой стороны.
- Файл можно перетащить мышью из списка или из файлового менеджера на панель любой деки.

## 9. Темп: ведущая дека, SYNC, цепочка до MC-707

Темп всего сета задаёт ведущая дека: приложение знает её BPM, подгоняет под него деки с включённым SYNC и передаёт его в DJ-202, который по MIDI-кабелю ведёт MC-707.

**Темп деки** = BPM сетки × текущая скорость воспроизведения.

**Выбор ведущей деки** (модуль `tempo/MasterSelector`, покрыт тестами):

1. Ведущей нет, дека начала играть и слышна в Master: она становится ведущей.
2. Ведущая остаётся ведущей, пока играет и слышна. Запуск других дек роль не отбирает.
3. Ведущая остановлена или перестала быть слышна: роль переходит к играющей слышимой деке, запущенной раньше остальных. Если таких нет, ведущей нет, а темп на выходе замирает на последнем значении.
4. Ручное назначение (SHIFT + SYNC на контроллере или щелчок по пометке на экране) делает деку ведущей сразу и держится, пока эта дека играет и слышна; дальше действует правило 3.

**SYNC** (кнопка на каждой деке, переключатель):

- Скорость ведомой деки = темп ведущей × k / BPM сетки ведомой, где k выбирается из 0,5, 1 и 2 так, чтобы скорость была ближе всего к 1. Диапазон ±8 % на SYNC не распространяется.
- Доли: при включении ближайшая доля ведомой плавно подводится к доле ведущей коротким изменением скорости (не скачком позиции), затем расхождение удерживается в пределах 5 мс.
- Джог на ведомой деке при включённом SYNC сдвигает целевое смещение долей, чтобы можно было поправить на слух.
- У трека с `steady: false` подгоняется только темп.
- SYNC на самой ведущей деке и SYNC без ведущей ничего не меняют; кнопка коротко мигает.
- Питч-фейдер ведущей двигает все ведомые деки и темп на выходе. Питч-фейдер ведомой деки при включённом SYNC не действует.

**Темп на выходе** (в DJ-202 и дальше в MC-707):

- Равен темпу ведущей деки; движение её питча передаётся сразу.
- При смене ведущей на деку с другим темпом значение плавно переходит к новому за N тактов (по умолчанию 4, настройка от 1 до 16).
- Обновления шлются не чаще 20 раз в секунду.

**Два пути доставки темпа в MC-707.** Какой из них работает, выясняется только на железе, поэтому код пишется под оба за одним интерфейсом `TempoOut`.

| Путь | Как работает | Состояние |
| --- | --- | --- |
| A. Через DJ-202 (основной) | Приложение сообщает темп контроллеру, тот шлёт MIDI clock на свой MIDI OUT | Протокол для DJ-202 не подтверждён. Образец: маппинг Mixxx для DJ-505, где синхронизация встроенного секвенсора работает по темпу, без подгонки долей |
| B. Прямой clock (запасной) | Приложение само шлёт MIDI clock (24 импульса на долю) в порт Direct clock out; нужен USB-MIDI-адаптер от ноутбука к MIDI IN MC-707 | Требует дополнительного адаптера. Зато импульсы можно привязать к сетке ведущей деки, и тогда совпадут и доли, а не только темп |

Генератор MIDI clock нужен в любом случае: его используют путь B и эмулятор DJ-202. Импульсы планируются по звуковым часам, а не по таймеру интерфейса.

Совпадение долей ведущей деки и грува MC-707 на пути A не гарантируется: трек подводится к груву джогом. Проверить на железе также, как MC-707 стартует под внешним clock (настройки MIDI Sync и RX Start Stop).

**Шина темпа** (`tempo/TempoBus`) даёт камере темп, положение внутри доли и внутри такта. Источник выбирается по приоритету:

1. Ведущая дека (темп и доли из её сетки).
2. MIDI clock от MC-707 по USB.
3. Определение по бочке в потоке MIX.
4. Ручное набивание (Tap).

Текущий источник показан рядом с значением темпа.

**Анализ трека.** Интерфейс `BeatAnalyzer` принимает декодированный трек и возвращает BPM, положение первой доли и признак ровного темпа. BPM ищется в диапазоне 70–180; ручные правки на деке: ×2, ÷2, сдвиг сетки влево и вправо, набивание.

## 11. Эмуляторы и тестовые сигналы

Эмуляторы реализуют те же интерфейсы слоя устройств, что и железо, и выбираются в тех же списках под именами `MC-707 (emulator)` и `DJ-202 (emulator)`. Весь остальной код не должен содержать ни одной проверки «это эмулятор».

**Эмулятор MC-707** — простой секвенсор, который играет текстовый файл паттерна и отдаёт звук в тех же каналах, что ожидаются от MC-707 (`IAudioInput`, 20 каналов, 48 кГц, плюс MIDI-порт). Похожесть на настоящий MC-707 не нужна: нужен понятный источник звука, который пользователь собирает сам в текстовом редакторе и видит матрицей.

Пример файла паттерна (`resources/patterns/default.txt`):

```text
# DEMO.TXT
NAME    DEMO
TEMPO   126
LENGTH  64              # ВСЕГО ШАГОВ, ОТ 16 ДО 256
GRID    16              # ШАГОВ В ТАКТЕ, ДЛЯ РАЗМЕТКИ МАТРИЦЫ

# ФРАГМЕНТЫ: ИМЯ = ШАГИ.  X АКЦЕНТ, x ОБЫЧНЫЙ УДАР
A = X000 x000 x000 x000
B = X000 x000 X0x0 x0XX
H = (10)X8

[1] DRUMS
KICK    A A A B
TICK    /2                    SC
CLAP    /8+4                  PP=3 RV=0.4
HAT     H
  PAN   = SIN(32) * 0.8       # ХЭТ ПЛАВНО ХОДИТ СЛЕВА НАПРАВО
  LEVEL = 0.5 + KICK * 0.3    # НА БОЧКЕ ХЭТ ГРОМЧЕ

[2] BASS  OCT=2
(1[C]111 0000  1[f]111 0000)X4

[3] PLUCK  OCT=4 ARP=UP SP=8
(1[C,E,G]111 1111)X4  (1[f,a,c]111 1111)X4

[4] PAD  W=1 RV=0.6
1[amin]111 1111 1111 1111

[5] LEAD  OCT=4 SCALE=AMIN
X0x0 x0x0 X0xx x0x0
  NOTE  = N*2 % 7 + B         # ТЕРЦИИ ПО ЛАДУ, КАЖДЫЙ ТАКТ НА СТУПЕНЬ ВЫШЕ
```

Правила формата:

- **Заглавные буквы.** Слова формата пишутся заглавными: шапка, типы треков, имена звуков, параметры, имена фрагментов, `X` в повторе. Приложение само пишет их только заглавными; набранные строчными понимает так же. Текст после `#` — комментарий, он не трогается.
- **Размер буквы = акцент.** Размер буквы имеет смысл ровно в двух местах: в ударе и в ноте. Заглавная — акцент: звук громче, а на сфере ярче и крупнее. Строчная — обычный звук.
- **Шапка.** `NAME` название; `TEMPO` темп в BPM (действует, когда эмулятор идёт по собственному темпу); `LENGTH` длина паттерна в шагах, от 16 до 256, по умолчанию 16; `GRID` число шагов в такте, по умолчанию 16. Один шаг — шестнадцатая нота.
- **Шаги.** `0` — тишина; `1` или `x` — обычный удар; `X` — удар с акцентом. Пробелы между шагами ничего не значат и нужны только глазу.
- **Повтор `( )XN`.** Группа в скобках повторяется N раз: `(1000)X4` даёт 16 шагов. Скобки можно вкладывать. `X` сразу после закрывающей скобки — всегда повтор, а не удар.
- **Равномерные удары `/N` и `/N+K`.** Обычный удар каждые N шагов, начиная со сдвига K: `/4` даёт удар в каждую долю, `/8+4` даёт удар на вторую и четвёртую доли. Заполняет всю длину паттерна. Только для строк барабанов.
- **Фрагменты.** Строка `ИМЯ = шаги` до первого трека определяет кусок с именем; дальше имя ставится вместо шагов: `A A A B`. Имя фрагмента не может совпадать со словом формата и не может состоять из одних букв `X`. Фрагмент может содержать ноты и повторы, но не другие фрагменты.
- **Длина строки.** Строка короче `LENGTH` повторяется по кругу; строка длиннее `LENGTH` — ошибка с указанием номера строки.
- **Треки.** Заголовок `[номер] ТИП параметры`, номер от 1 до 8. Каждый трек идёт в свою стереопару и виден на сфере одним источником.
- **Трек `DRUMS`.** До 16 строк, каждая строка — отдельный звук. Все строки звучат в одной паре каналов: 16 подканалов воспринимаются как один канал. Первое слово строки выбирает звук: `KICK`, `SNARE`, `CLAP`, `TICK`, `HAT`, `OPENHAT`, `TOM`, `RIM`, `PERC`, `NOISE`.
- **Нотные треки `BASS`, `LEAD`, `PLUCK`, `PAD`.** Тип трека сразу выбирает звук. Одна строка шагов. `[нота]` сразу после `1` задаёт высоту с этого шага. Следующие `1` без скобок держат ту же ноту одной длинной нотой, `0` её обрывает; новая скобка начинает новую ноту.
- **Ноты.** `C D E F G A B` с акцентом или `c d e f g a b` без него. Диез `C#` (бемоли записываются через диез: `A#` вместо си-бемоля), октава цифрой (`C3`); без цифры берётся `OCT` трека. Аккорд: перечислением `[C,E,G]` или именем `[CMAJ]`, `[CMIN]`, `[C7]`; акцент аккорда определяет его первая буква (`[amin]` без акцента).
- **Арпеджиатор** (только нотные треки): `ARP=UP`, `ARP=DOWN`, `ARP=UPDOWN`, `ARP=RANDOM`. Шаг арпеджио по умолчанию шестнадцатая; другой задаётся через дробь: `ARP=UP/8`, `ARP=UP/32`. Пока в строке стоят единицы, перебираются ноты текущего аккорда.

Параметры пишутся в заголовке трека или в конце строки барабанов. У каждого есть короткая и полная форма, работают обе:

| Коротко | Полностью | Что делает | Что видно на сфере |
| --- | --- | --- | --- |
| `P=0.4` | `PAN` | Место по панораме, от −1 до 1 | Точка смещена влево или вправо |
| `W=1` | `WIDTH` | Ширина, от 0 (моно) до 1 | Звук расплывается по бокам |
| `LV=0.8` | `LEVEL` | Громкость, от 0 до 1 | Яркость |
| `OCT=2` | `OCTAVE` | Октава нотного трека | Высота |
| `INV` | `PHASE=INV` | Противофаза | Звук уходит назад |
| `AP=4` | `AUTOPAN` | Ходит слева направо и обратно, полный круг за 4 доли | Точка качается по передней дуге |
| `SP=8` | `SPIN` | Обходит вокруг за 8 долей: панорама и фаза меняются согласованно | Точка едет вокруг зрителя: спереди, сбоку, сзади, с другого бока |
| `SC` | `SCATTER` | Каждый удар попадает в случайное место панорамы | Вспышки в разных сторонах |
| `PP=3` | `PINGPONG` | Эхо прыгает между сторонами с шагом 3 шестнадцатых | Повторы поочерёдно слева и справа, затухая |
| `RV=0.4` | `REVERB` | Простая стереореверберация, от 0 до 1 | Сухой звук спереди, хвост расплывается по бокам |

Эффекты есть только у эмулятора: на настоящем устройстве звук двигают его собственные эффекты, приложение их только показывает. `SPIN` в наушниках слышен не как облёт по кругу, а как уход вбок с размытием и возврат с другой стороны; на сфере круг виден целиком.

**Формулы.** Высоту ноты, место в панораме и громкость можно не писать числами, а считать формулой. Формула пишется отдельной строкой сразу под строкой шагов, к которой относится; отступ в начале строки ничего не значит. Формула считается заново в момент каждого удара или начала ноты.

- `NOTE = формула` (только нотные треки) задаёт высоту. Результат — номер ступени лада: 0 — тоника, 1 — следующая ступень вверх, −1 — ступень вниз; ступени за пределами лада переходят в соседнюю октаву. Дробный результат округляется вниз. Лад задаётся параметром трека `SCALE`: `SCALE=AMIN`, `SCALE=CMAJ`, `SCALE=APENT` (минорная пентатоника); без `SCALE` берётся `CMAJ`. Нота, написанная в скобках прямо на шаге, сильнее формулы. Арпеджиатор с формулой не сочетается: он перебирает только аккорды из скобок.
- `PAN = формула` задаёт место в панораме от −1 до 1 и заменяет параметр `P`. Эффекты движения работают поверх.
- `LEVEL = формула` задаёт громкость от 0 до 1 и заменяет параметр `LV`. Акцент прибавляется сверху.
- В треке `DRUMS` строки `PAN` и `LEVEL` относятся только к тому звуку, под строкой которого стоят.
- Результат `PAN` и `LEVEL` за пределами допустимого обрезается до границы. Деление на ноль даёт 0.

Что можно писать в формуле:

| Запись | Значение |
| --- | --- |
| `N` | Номер удара или ноты в своей строке, считая с 0; в начале паттерна сбрасывается |
| `S` | Номер шага в паттерне, с 0 |
| `B` | Номер такта, с 0 |
| `RND(K)` | Случайное целое от 0 до K−1 |
| `RND` | Случайное дробное от 0 до 1 |
| `SIN(P)` | Волна от −1 до 1 с периодом P шагов; на шаге 0 равна 0 |
| `KICK`, `HAT` и другие имена звуков | 0, если на этом шаге звук трека `DRUMS` молчит; 1 при обычном ударе; 2 при акценте |
| `+ - * / %` и скобки | Обычная арифметика; `%` — остаток от деления |

Формулы пишутся заглавными буквами; размер буквы в них ничего не значит. Буква `B` в формуле — всегда номер такта, даже если есть фрагмент с именем `B`: фрагменты действуют только в строках шагов. Слова `NOTE`, `PAN`, `LEVEL`, `N`, `S`, `RND`, `SIN` нельзя брать именами фрагментов. Формулы правятся только в файле; в окне эмулятора ноты, посчитанные формулой, показаны так же, как написанные вручную. Ошибка в формуле обрабатывается как любая ошибка файла: играет прежний паттерн, показан номер строки.

**Песня: цепочка паттернов.** Чтобы собрать целый трек, паттерны выстраиваются в цепочку отдельным файлом в той же папке. Файл песни отличается от паттерна первым словом шапки: `SONG` вместо `NAME`.

```text
# LIVE.TXT
SONG    LIVE
TEMPO   126             # НЕОБЯЗАТЕЛЬНО: ОДИН ТЕМП НА ВСЮ ПЕСНЮ

INTRO   X2              # ФАЙЛ INTRO.TXT, ДВА РАЗА
DEMO    X4
BREAK                   # БЕЗ ЧИСЛА: ОДИН РАЗ
DEMO    X8
```

- Каждая строка — имя файла паттерна без `.TXT` и число повторов `XN`; без числа паттерн играет один раз. Один повтор — весь паттерн от начала до конца (его `LENGTH`).
- Строки играются сверху вниз; после последней песня начинается заново. Переход к следующему паттерну происходит ровно в конце текущего, без паузы.
- `TEMPO` в песне заменяет темп всех её паттернов. Без него каждый паттерн идёт в своём темпе. Темп действует, только когда эмулятор идёт по собственному темпу.
- Файл песни пишется заглавными буквами; размер буквы в нём ничего не значит, имена файлов ищутся без учёта регистра. Песня не может ссылаться на другую песню.
- Окно эмулятора показывает список строк песни с отметкой текущей и номером повтора, а ниже матрицу паттерна, который играет сейчас. Щелчок по строке песни переходит к ней в конце текущего паттерна. Порядок и повторы правятся только в файле.
- Файл песни перечитывается при сохранении, как и паттерн. Ошибка в песне или в любом её паттерне (в том числе ненайденный файл) не останавливает звук: продолжает играть прежний вариант, в окне показаны файл, номер строки и причина.

Поведение эмулятора:

- Окно эмулятора показывает паттерн матрицей: строки звуков, клетки шагов, бегущая метка текущего шага; акценты нарисованы ярче обычных ударов. Длинный паттерн показан страницей в 16, 32 или 64 шага, которая листается вслед за меткой; границы тактов размечены по GRID. Щелчок по клетке меняет её по кругу: тишина, обычный удар, акцент. Изменение сразу записывается обратно в файл; комментарии и остальной текст файла при этом сохраняются. Клетка из фрагмента меняет сам фрагмент, то есть все места, где он стоит; эти места подсвечиваются. Клетка из повтора в скобках или из равномерных ударов разворачивает сокращение этой строки в обычные шаги и меняет одну клетку. Ноты, аккорды и параметры правятся только в файле.
- Файл перечитывается при каждом сохранении, без перезапуска; изменение вступает с начала следующего такта.
- При ошибке в файле продолжает играть прежний паттерн, а в окне показаны номер строки и причина простыми словами.
- Паттерн или песня (цепочка паттернов) выбирается из списка файлов папки паттернов. Встроенный `default.txt` содержит 8 треков, разнесённых по панораме, ширине, частотам и фазе, с акцентами и эффектами движения, чтобы сфера была заполнена со всех сторон.
- Звуки синтезируются простыми генераторами; красота звука не цель.
- Канал EXT IN получает копию выхода Master приложения, как по кабелю на сцене. MIX = сумма треков и EXT IN.
- Панель: выключатель каждого трека, источник темпа (внешний MIDI clock по умолчанию или собственный из файла), карта каналов, режим «только стерео» (отдаёт одну пару), имитация потери устройства.
- Шлёт MIDI clock в своём текущем темпе, как настоящий MC-707 по USB.
- Вместо паттерна может играть по кругу многоканальный WAV, записанный с настоящего устройства.

**Эмулятор DJ-202** (MIDI-порт, простое окно с кнопками и ползунками; внешний вид контроллера повторять не нужно):

- Работает на уровне MIDI: шлёт те же байты, что описаны в `dj202.json`, и принимает сообщения подсветки. Поэтому вместе с ним проверяется и сам код маппинга.
- Элементы: всё из таблицы раздела 10, включая SHIFT, DECK, 8 пэдов на сторону и энкодер. Управление мышью и клавиатурой, когда окно эмулятора в фокусе.
- Принимает темп от приложения и шлёт MIDI clock на виртуальный MIDI OUT, соединённый с эмулятором MC-707.
- Собственного звука у него нет: Master и Phones приложения идут в выходы, выбранные в Settings.

**Тестовые сигналы** (подставляются вместо трека 1 эмулятора MC-707): тон по центру; проход панорамы; проход частоты; переход из фазы в противофазу; независимый шум; тишина. Ожидаемая картинка для каждого описана в разделе 5.

## 12. Интерфейс

Все подписи в приложении на английском. Фон почти чёрный, панели тёмно-серые, текст светло-серый; цвет на экране несут только источники сферы, полосы вейвформ и состояния (запись красным, предупреждение янтарным). Элементы крупные и контрастные. Главное правило раскладки: на виду только то, на что смотрят во время игры; всё остальное убрано в панели, которые открываются по кнопке.

**Один экран и слои.** Главное окно одно. Сфера всегда на фоне и занимает всё окно; всё остальное — слои поверх неё. Слой открывается и закрывается, не останавливая звук и картинку. Экранов, которые заменяют друг друга, нет. Это решение пользователя заменяет прежние отдельные экраны Sphere, DJ и Settings и отдельные окна эмуляторов.

| Слой | Откуда появляется | Как открыть | Что внутри |
| --- | --- | --- | --- |
| Decks | Снизу, поднимается поверх сферы | Кнопка DECKS или Tab | Бегущие вейвформы, две плашки дек, список треков |
| MC-707 emulator, DJ-202 emulator | Вкладки той же нижней панели | Кнопка-вкладка в нижней панели; вкладка есть, только когда в устройствах выбран эмулятор | Матрица паттерна и цепочка песни; панель контроллера |
| Sources | Слева | Кнопка Sources или S | На каждый источник: цвет, уровень, усиление, выключатель |
| Look | Справа | Кнопка Look или L | Палитра, Rate, Decay, Density, ориентиры, плоские карты, пролёт камеры и его четыре модулятора |
| Settings | Поверх всего, широкой панелью | Кнопка Settings | Вкладки настроек |
| Setup wizard | Поверх всего | Кнопка Setup wizard; сам при первом запуске | Шесть шагов первой настройки |
| Start check | Поверх всего | Сам при каждом запуске; щелчок по предупреждению в строке состояния | Список проверок готовности |
| Help | Поверх всего | Кнопка ? или F1 | Подписи к тому, что сейчас на экране, и клавиши |

Правила слоёв:

- Верхняя строка видна всегда: название, кнопки DECKS, Sources, Look, Setup wizard, Settings и ?. Нижняя строка видна всегда: кнопка Rec, время записи, темп и его источник, состояние одной фразой (all ok или текст предупреждения).
- Sources, Look и нижняя панель могут быть открыты одновременно. В нижней панели показана одна вкладка; её высота меняется перетаскиванием верхней границы и запоминается.
- Settings, Setup wizard, Start check и Help открываются по одному и лежат поверх остальных слоёв; сфера и деки под ними остаются видны и продолжают работать.
- Esc закрывает верхний слой. Клавиша H прячет всё, включая верхнюю и нижнюю строки, и оставляет чистую сферу; повторное нажатие возвращает как было.
- Мышь по свободной части сферы всегда управляет камерой. Отдельных режимов ноутбука (прежние DJ view и Shared sphere) больше нет.
- Везде, где в разделе 11 сказано «окно эмулятора», имеется в виду вкладка нижней панели.

**Схема переходов:**

```text
 запуск --[первый раз]--> Setup wizard --+
    |                                   v
    +----------------------------> Start check --Go--> СФЕРА (главное окно)
                                        ^                |
            предупреждение в строке ----+                |
            состояния (щелчок)                           |
                                                         |
   Tab ......... нижняя панель: Decks | MC-707 emulator | DJ-202 emulator
   S ........... Sources (слева)
   L ........... Look (справа)
   кнопки ...... Settings | Setup wizard | Help      (поверх всего)
   Start check: кнопка Fix у строки --> нужная вкладка Settings или шаг wizard
   Esc ......... закрыть верхний слой        H ... спрятать всё
```

**Start check** (при каждом запуске). Короткий список, у каждой строки отметка «в порядке» или «проблема» и кнопка Fix, которая открывает нужную вкладку Settings или шаг wizard:

- вход звука подключён, уровни движутся;
- контроллер подключён;
- выходы Master и Phones открыты;
- папка треков доступна;
- папка записей доступна, свободного места хватает, `ffmpeg` найден;
- экран для зрителей найден (если был включён в прошлый раз).

Кнопка Go закрывает проверку и доступна всегда, даже с проблемами: на сцене нельзя застрять на проверке (решение разработчика, с пользователем не обсуждалось). Звук и картинка работают уже во время проверки.

**Setup wizard.** Шесть шагов, каждый спрашивает одну вещь и тут же даёт её проверить; кнопки Back, Skip, Next:

1. Sound in: устройство входа или эмулятор; проверка — уровни движутся.
2. Controller: DJ-202 или эмулятор; проверка — нажать любую кнопку.
3. Sound out: Master и Phones; проверка — тестовый тон в каждый выход.
4. Tracks folder.
5. Recording folder; проверка — пробная запись на две секунды.
6. Check: тот же список, что в Start check.

**Help.** Кнопка ? есть в верхней строке и в заголовке каждой панели. Она кладёт поверх текущего вида пронумерованные подписи к открытым панелям и список клавиш, которые сейчас действуют. Тексты справки короткие, по одному-двум предложениям на панель.

**Нижняя панель Decks.** Сверху бегущие вейвформы на всю ширину с общей меткой «сейчас»: две деки в фокусе крупно, две остальные узкими полосками. Ниже две плашки дек: номер, название, оставшееся время, BPM, питч, пометка MASTER или SYNC, обзорная полоска трека. Ниже список треков с поиском. Hot cue, точка cue и петли показаны метками на вейвформах. Полного микшера на экране нет: ручки, фейдеры и пэды есть на контроллере. Вместо него на плашке каждой из четырёх дек стоят маленькие индикаторы (решение пользователя): полоска фейдера канала, три метки EQ (low, mid, high), метка фильтра, trim и значок CUE. Индикаторы только показывают текущее значение, мышью не двигаются. Две деки в фокусе контроллера показаны крупными плашками, две остальные — узкими плашками под ними, с теми же индикаторами; так видно положение ручек дек 3 и 4, когда контроллер переключён на 1 и 2. Когда ручка контроллера ещё не подхватила значение деки (мягкий подхват, раздел 8), рядом с меткой показано ещё и положение самой ручки. Правка сетки битов (сдвиг, ×2, ÷2, Tap) открывается щелчком по BPM на плашке деки.

**Вкладки эмуляторов.** MC-707 emulator: выбор файла, темп, цепочка песни одной строкой, матрица паттерна; источник темпа, размер страницы, режим «только стерео» и имитация потери устройства лежат под кнопкой More. DJ-202 emulator: на виду то, что нужно, чтобы сыграть трек (LOAD, CUE, PLAY, SYNC, джог, питч, пэды, фейдеры, кроссфейдер, выбор трека); trim, EQ, фильтр, предпрослушка, KEY LOCK, SHIFT и деки 3 и 4 под кнопкой More.

**Settings** (вкладки; на каждой короткий список, редкое открывается кнопкой):

| Вкладка | На виду | По кнопке |
| --- | --- | --- |
| Devices | Вход звука, контроллер, путь темпа A или B, длина перехода темпа в тактах | Карта каналов, дополнительные входы, MIDI-порты, MIDI Monitor |
| Audio out | Устройство и пара каналов для Master и для Phones, Monitor | Размер звукового блока |
| Folders | Папка треков, папка записей, название сета | Шаблон имени файла |
| Recording | Формат аудио, разрешение и к/с видео | Качество, порог автостарта, предзапись |
| Look | Палитра, ступень качества, надпись (включена, угол, размер), дисплей для зрителей | Цвета отдельных источников |
| Keys | Назначаемые действия с кнопкой Assign |  |
| Maintenance | Состояние и кнопки обслуживания, см. ниже |  |

**Maintenance.** Сверху состояние: время работы, память и её тенденция (steady или growing), кадры в секунду, пропуски звуковых блоков, размер кэша. Ниже кнопки:

| Кнопка | Что делает | Звук дек |
| --- | --- | --- |
| Refresh picture | Перезапускает рендер и анализ, освобождает видеопамять | Не прерывается |
| Reconnect devices | Закрывает и заново открывает вход звука и MIDI-порты | Не прерывается; выход Master не трогается |
| Unload idle tracks | Выгружает треки из дек, которые стоят на паузе и не слышны | Не прерывается |
| Clear waveform cache | Удаляет кэш вейвформ; они пересчитываются при загрузке трека. Файлы данных рядом с треками не трогает | Не прерывается |
| Clear leftover recordings | Удаляет временные файлы записи, оставшиеся после сбоя | Не прерывается |
| Reset settings | Возвращает настройки по умолчанию; треки, метки и записи не трогает | Доступна, только когда деки не играют |

Три кнопки очистки и сброса спрашивают подтверждение прямо в строке (кнопка превращается в Confirm на несколько секунд), без модального окна.

**Самонаблюдение.** Кнопки обслуживания — страховка; программа не должна замедляться сама. Приложение раз в минуту снимает память, время кадра и число пропусков звуковых блоков и пишет их в журнал. Если память растёт десять минут подряд или кадр не укладывается в бюджет, в строке состояния появляется предупреждение со ссылкой на Maintenance, а ступень качества графики снижается сама (раздел 6). Пороги начальные, подбираются на машине.

**Растягивание под окно.** Интерфейс тянется под любой размер окна, фиксированных размеров макета нет:

- сфера, вейвформы, матрица паттерна, список треков и поля настроек занимают всю доступную ширину;
- боковые панели Sources и Look держат свою ширину (около 300 точек) и ложатся поверх сферы, не сжимая её;
- нижняя панель занимает долю высоты окна (по умолчанию около 60 %);
- минимальный размер окна 1024 × 600; на узком окне кнопки верхней строки сворачиваются в значки, плашки дек встают одна под другой;
- программный кадр для зрителей и записи от размера окна ноутбука не зависит (раздел 6).

**Клавиши по умолчанию** (все переназначаются; набор предложен разработчиком, с пользователем не согласовывался):

| Клавиша | Действие |
| --- | --- |
| Tab | Открыть или закрыть нижнюю панель Decks |
| S, L | Панели Sources и Look |
| H | Спрятать или показать все панели и строки |
| Esc | Закрыть верхний слой |
| F1 или ? | Help |
| M | Плоские карты: показать или спрятать |
| G | Ориентиры: показать или спрятать |
| P | Следующая палитра |
| F | Пролёт камеры |
| Home | Сброс вида |
| T | Tap tempo |
| F9 | Окно зрителей |
| F11 | Полный экран |
| Ctrl + R, Ctrl + Shift + R | Взвести запись аудио, видео |
| Ctrl + . | Остановить запись |

Клавиши-буквы не срабатывают, пока курсор стоит в поле ввода (поиск треков, название сета). Стрелки, Page Up и Page Down двигают камеру по кубу, Shift ускоряет (раздел 6).

Окно зрителей никогда не показывает слои, курсор и сообщения: только программный кадр. Все предупреждения идут в нижнюю строку на ноутбуке. Модальных окон нет: Settings, Setup wizard, Start check и Help — панели поверх, которые не останавливают ни звук, ни картинку. После остановки записи в нижней строке на несколько секунд появляется имя файла и кнопка Show in folder. При закрытии приложения идущая запись сначала дописывается и сохраняется.

## 13. Настройки и файлы на диске

| Что | Где (Linux) |
| --- | --- |
| Настройки | `~/.config/pejeded-studio/settings.json` |
| Кэш вейвформ и запасное место для файлов данных | `~/.cache/pejeded-studio/` |
| Журнал | `~/.local/state/pejeded-studio/log/`, по файлу на запуск, хранится 20 последних |

На macOS настройки, кэш и журнал лежат в стандартных папках приложения в `~/Library`.

    "monitor": false
  },
  "tracks": { "folder": "" },
  "recording": {
    "folder": "", "nameTemplate": "{date}_{time}_{set}", "setName": "set",

## 14. Надёжность на сцене: правила для кода

Главное правило: что бы ни случилось с картинкой, записью или интерфейсом, звук дек не прерывается.

- В звуковых колбэках нет выделения памяти, блокировок, файлового ввода-вывода, журнала и вызовов интерфейса.
- Любой обмен со звуковым потоком идёт через очереди без блокировок или атомарные значения.
- Исключение в рендере, записи или анализе ловится на границе своего потока: подсистема перезапускается, в строке состояния появляется предупреждение, деки продолжают играть.
- Потеря любого USB-устройства не завершает приложение (раздел 4).
- Модальных диалогов во время работы нет; подтверждения возможны только на экране Settings.
- Графика снижает качество сама, если не укладывается в кадр (раздел 6).
- Видеозапись теряет кадры, но не тормозит остальное (раздел 7).
- Журнал пишется отдельным потоком; в него попадают смена состояний устройств, переполнения буферов, пропуски кадров, пропуски звуковых блоков (xrun), ошибки.
- Счётчик пропусков звуковых блоков виден в строке состояния. Цель для двухчасового сета: ноль.
- Размер звукового блока по умолчанию 256 отсчётов (около 5 мс на 48 кГц), настраивается; проверить устойчивость на машине под PipeWire.
- После перезапуска приложение готово играть без настройки: всё восстанавливается из файла настроек. Время от запуска до готовности не больше 5 секунд.

## 15. Этапы и критерии готовности

Этапы идут по порядку; следующий не начинается, пока не выполнены критерии предыдущего. Этапы 1–7 проверяются целиком на эмуляторах, без железа. Общее требование к каждому этапу: проект собирается в контейнере без предупреждений, все автотесты (модульные и сквозные) проходят в контейнере, каждый проверяемый программой критерий этапа закрыт тестом, приложение работает 30 минут без пропусков звуковых блоков и роста памяти.

**Этап 1. Каркас.** Сборка, окно, слой устройств, выбор входа и выходов, эмулятор MC-707, тестовые сигналы, настройки.

- [ ] Сборка и автотесты работают в контейнере; собранная программа запускается на машине: окно открывается, звук слышен, MIDI-порты видны. Маковская версия собирается на GitHub, проходит там те же автотесты и скачивается архивом. Фактическое окружение записано в `docs/environment.md`.
- [ ] В списке входов видны эмулятор и настоящие устройства системы; выбор сохраняется между запусками.
- [ ] Панель Sources показывает 9 индикаторов уровня, они движутся под звук эмулятора; выключатель трека в эмуляторе гасит свой индикатор. Правка файла паттерна в текстовом редакторе слышна и видна в матрице без перезапуска; ошибка в файле не останавливает звук.
- [ ] Master и Phones назначаются на динамики, наушники ноутбука и HDMI; смена без перезапуска и без щелчка.
- [ ] Monitor подмешивает MIX эмулятора в выбранный выход.
- [ ] Имитация потери устройства даёт предупреждение и возврат без перезапуска.

**Этап 2. Сфера.** Анализ, раскладка в объём, вид «нити», ручная камера, палитры, Decay, Density, ориентиры, плоские карты.

- [ ] Модульные тесты анализа проходят для всех шести строк таблицы тестовых сигналов из раздела 5.
- [ ] На экране те же сигналы встают в описанные места.
- [ ] Восемь треков эмулятора различимы по цвету и месту; выключение источника в панели убирает его со сферы.
- [ ] Камера находится внутри звука: взгляд поворачивается мышью, колесо двигает камеру к звуку и обратно, клавиша сброса возвращает в центр. Стрелки, Page Up и Page Down двигают камеру по кубу. При любом положении кадр заполнен от края до края, шара как предмета не видно.
- [ ] Форма пропадает сразу за звуком: при Decay по умолчанию через 0,3 с после конца звука её не видно; следов и шлейфов нет. Одна барабанная дорожка эмулятора показывает бочку, хэт и клэп в трёх разных местах одним цветом. Сухой звук с резкими атаками стоит ближе размытого. Нити — настоящие сигналы полос: у тестового тона ровная спираль, у шума ломаная нить; случайных чисел в отображении нет, один и тот же звук даёт один и тот же кадр. Два почти равных по силе звука в одном месте белеют. Вид совпадает с прототипом docs/prototype/sound-space.html, пользователь это подтвердил.
- [ ] 60 к/с на ступени Medium на машине разработки.

**Этап 3. Камера и темп.** Пролёт с четырьмя модуляторами, шина темпа (источники 2–4).

- [ ] Камера в пролёте проходит сквозь формы без рывков и без заливки всего кадра одним цветом.
- [ ] Каждый модулятор пролёта включается отдельно, и его действие видно: тишина замедляет камеру, бочка толкает, камера смотрит на звучащую зону, траектория меняется ровно по тактам.
- [ ] Камера в пролёте не выходит наружу: звук всё время окружает зрителя.
- [ ] Темп берётся из MIDI clock эмулятора; при отключённом clock определяется по бочке с ошибкой не больше 1 BPM; Tap работает.
- [ ] Плоские карты и ориентиры включаются и выключаются клавишами; в окно зрителей карты не попадают.

**Этап 4. Запись.** Аудио, видео со звуком, надпись, вкладки Recording и Visual.

- [ ] Взведённая запись стартует от первого звука; в файле есть 2 с до него.
- [ ] WAV и FLAC открываются в проигрывателе; звук совпадает с MIX эмулятора.
- [ ] MP4 1920×1080, 60 к/с проигрывается; в кадре нет панелей; надпись PEJEDED STUDIO на месте и отключается.
- [ ] На записи длиной 60 минут расхождение звука и картинки в конце не больше одного кадра (проверка по тестовому щелчку со вспышкой).
- [ ] Принудительное завершение `ffmpeg` не останавливает звук и аудиозапись.
- [ ] После принудительного завершения приложения оставшиеся файлы открываются, и при следующем запуске предлагается склейка.

**Этап 5. DJ: основа.** Четыре деки, микшер, предпрослушка, вейвформы, список треков, маппинг, эмулятор DJ-202, вход EXT IN эмулятора MC-707.

- [ ] Треки MP3, FLAC, WAV, AIFF грузятся кнопкой LOAD эмулятора и перетаскиванием; трек играет не позже чем через 3 с после загрузки.
- [ ] Все элементы таблицы раздела 10, кроме SYNC, пэдов и KEY LOCK, работают с эмулятора через MIDI и файл маппинга.
- [ ] Переключение DECK не меняет звук, пока ручка не прошла сохранённое значение.
- [ ] Предпрослушка: канал с CUE слышен в Phones при закрытом фейдере и не слышен в Master.
- [ ] Две крупные и две узкие вейвформы идут мимо общей метки; полосы раскрашены; при 60 к/с нет дрожания.
- [ ] Список треков: поиск, сортировка по трём колонкам, прокрутка энкодером.
- [ ] LOAD на играющей слышимой деке отклоняется; за 30 с до конца дека мигает.
- [ ] Звук дек появляется на сфере как источник EXT одного цвета.

**Этап 6. DJ: темп.** Анализ BPM и сетки, файл данных, ведущая дека, SYNC, темп на выходе, keylock, hot cue, петли.

- [ ] На наборе из 20 танцевальных треков с ровным темпом BPM определён верно (с точностью 0,1; ошибка вдвое считается отдельно) минимум у 18.
- [ ] Правки сетки работают и переживают повторную загрузку трека; файл `.pjd.json` лежит рядом с треком.
- [ ] Модульные тесты покрывают все четыре правила выбора ведущей деки и выбор k для половинного и двойного темпа.
- [ ] SYNC сводит два трека с разным BPM: через 5 минут доли расходятся не больше чем на 5 мс.
- [ ] Трек 70 BPM встаёт к ведущему 140 BPM без ускорения вдвое.
- [ ] Питч ведущей деки меняет темп ведомой деки и темп эмулятора MC-707; при смене ведущей темп эмулятора переходит плавно за заданное число тактов.
- [ ] Keylock: при ±8 % тон не меняется, звук без заметных искажений; выключение возвращает поведение винила.
- [ ] Четыре hot cue ставятся, вызываются, удаляются и сохраняются; петли 1, 2, 4, 8 долей замыкаются без щелчка и держат долю.

**Этап 7. Сцена.** Окно зрителей, два режима ноутбука, назначаемые действия, ступени качества, устойчивость.

- [ ] Окно зрителей включается и выключается на ходу на втором дисплее; в нём нет панелей и курсора.
- [ ] Нижняя панель Decks открывается и закрывается одной клавишей поверх сферы. Settings, Setup wizard, Start check и Help открываются поверх, не прерывая звук и картинку; все кнопки Maintenance работают; интерфейс не ломается при любом размере окна от 1024 × 600.
- [ ] Любое действие из раздела 10 назначается на клавишу и на кнопку эмулятора; привязки переживают перезапуск.
- [ ] При искусственной перегрузке видеокарты ступень качества снижается сама, звук не прерывается.
- [ ] Прогон 2 часа на эмуляторах с видеозаписью, окном зрителей и сменой треков: ноль пропусков звуковых блоков, память не растёт.
- [ ] Перезапуск приложения возвращает все настройки, готовность не позже 5 с.

**Этап 8. Настоящее железо.** Проверки из раздела 16, правка карты каналов и маппинга, выбор пути темпа.

- [ ] Все пункты раздела 16 пройдены, результаты записаны в `docs/hardware-notes.md`.
- [ ] Все записи `dj202.json` помечены `verified: true`.
- [ ] Грув MC-707 идёт в темпе ведущей деки по пути A или B.
- [ ] Полный сет длиной 1 час на железе с видеозаписью без сбоев.

**Этап 9. macOS.** Сборка и проверка на старом и новом маке.

- [ ] Версия macOS и модель старого мака записаны; минимальная версия системы в сборке выставлена под него.
- [ ] Программа, скачанная с GitHub, запускается на обоих маках без установки чего-либо ещё; сфера даёт 60 к/с хотя бы на ступени Low.
- [ ] MC-707 с драйвером Roland и DJ-202 работают так же, как в Linux.
- [ ] Системные разрешения на звуковой вход запрашиваются корректно.

## 16. Проверки на железе и источники

Эти вопросы нельзя закрыть без устройств. Первый важнее остальных: от него зависит вся цепочка темпа.

- [ ] **Темп в DJ-202.** Принимает ли контроллер темп от программы тем же способом, что DJ-505 в маппинге Mixxx, и шлёт ли при этом MIDI clock на разъём MIDI OUT. Если нет, включается путь B и нужен USB-MIDI-адаптер.
- [ ] **Старт MC-707 под внешним clock.** Какие настройки MIDI Sync и RX Start Stop нужны, чтобы грув шёл в темпе контроллера и запускался кнопкой на самом MC-707.
- [ ] **Микрофон DJ-202.** Подмешивается ли он в выход Master самим контроллером, без программы. Если нет, приложению придётся пропускать микрофон через себя, и это отдельная задача.
- [ ] **Каналы DJ-202.** Сколько выходных каналов видит Linux и какие пары идут в Master и Phones; какие ручки (Master, Phones, MIXING) шлют MIDI, а какие работают внутри контроллера; есть ли кнопка KEY LOCK.
- [ ] **MIDI-коды DJ-202.** Сверить каждый элемент через MIDI Monitor с файлом маппинга, включая джоги и подсветку.
- [ ] **Режим USB у MC-707.** В каком режиме USB Driver (VENDOR или GENERIC) Linux видит много каналов и сколько их; ожидается 20 входов.
- [ ] **Порядок каналов MC-707.** Какие пары отвечают за MIX, TRACK 1–8 и EXT IN; поправить карту каналов по умолчанию.
- [ ] **EXT IN в USB.** Звук дек приходит отдельной парой; входит ли он ещё и в поток MIX (от этого зависит, попадут ли деки в запись).
- [ ] **Частота дискретизации MC-707** по USB и настройка USB Mix Select (до или после общего эффекта).
- [ ] **MIDI clock от MC-707** приходит в Linux после включения MIDI Sync Out USB.
- [ ] **Задержка.** Размер блока, при котором деки играют через DJ-202 без пропусков, и ощущение от джога.
- [ ] **macOS.** Версия системы и модель старого мака; ноутбук и видеокарта для сцены.

Команды для первой проверки в Linux при подключённых устройствах:

```text
arecord -l                 # звуковые входы: ищем MC-707
aplay -l                   # звуковые выходы: ищем DJ-202
cat /proc/asound/cards     # имена карт
cat /proc/asound/card*/stream0   # число каналов и частоты
amidi -l                   # MIDI-порты
aseqdump -l                # порты секвенсора
aseqdump -p <порт>         # смотреть входящие MIDI-сообщения, в том числе clock
pw-cli ls Node             # узлы PipeWire
```
