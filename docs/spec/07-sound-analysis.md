# 7. Анализ звука

> Часть задания PEJEDED STUDIO, версия 2. Оглавление и список «что читать на каком этапе»: [README.md](README.md). Ссылка «раздел N» в тексте ведёт в файл с номером N.

Место звука в кубе вычисляется только из звука: панорама даёт место влево-вправо, частота — высоту, сухость — расстояние (сухой близко, размытый далеко), фаза между каналами — ширину формы. Ручной расстановки нет, случайных чисел в расчёте нет: один и тот же звук всегда даёт одну и ту же картинку.

**Как идёт измерение.** Измерение привязано к счёту отсчётов звука, а не к кадрам экрана, поэтому повторяется точно.

| Параметр | Значение |
| --- | --- |
| Окно N | 2048 отсчётов при 44,1 и 48 кГц, 4096 при 88,2 и 96 кГц (около 43 мс); окно Ханна |
| Шаг измерения | 1/60 секунды по счёту отсчётов (800 отсчётов при 48 кГц). На каждом шаге берутся последние N отсчётов каждого источника |
| Полосы | 32, логарифмически от 30 Гц до 16 кГц |
| Источник | Стереопара или один канал (тогда L = R); до 12 источников, на сцене 9 (8 треков и EXT IN) |
| Порог активности источника | RMS выше −60 dBFS; у неактивного источника полосы не считаются, уровни гаснут |
| Съём (Rate) | В картинку уходит каждый k-й шаг: 60, 30, 20, 15 или 10 раз в секунду, по умолчанию 30 |

Границы полос и их бины спектра (sr — частота дискретизации):

```text
f(b)  = 30 * (16000 / 30) ^ (b / 32)                 b = 0..32, Гц
lo(b) = max( 1, floor( f(b) * N / sr ) )
hi(b) = min( N / 2, max( lo(b) + 1, ceil( f(b+1) * N / sr ) ) )
бины полосы b: k = lo(b) .. hi(b) - 1
```

**На каждом шаге для каждой полосы каждого источника** (L\[k\], R\[k\] — спектры окна, dt = 1/60 с):

```text
PL = sum |L[k]|^2      PR = sum |R[k]|^2      C = sum Re( L[k] * conj(R[k]) )

dB    = 10 * log10( (PL + PR) * 16 / N^2 + 1e-12 ) + усиление источника в дБ
        (полная синусоида в одном канале даёт около 0 дБ)
raw   = clamp( (dB + 58) / 52, 0, 1 )                -58 дБ -> 0,   -6 дБ -> 1
pan   = (PR - PL) / (PR + PL + eps)                  -1 слева ... +1 справа
corr  = C / sqrt(PL * PR + eps), в пределах -1..1    +1 в фазе ... -1 в противофазе
        если один канал тише другого больше чем на 40 дБ, corr = 1

rise   = raw - level33                               level33: сглаженный level этой полосы 1/30 с назад (два шага)
attack = max( attack * exp(-dt / 2 с), clamp(2.5 * rise, 0, 1) )      самый резкий недавний скачок громкости
onset  = max( onset - dt / 0.1 с,       clamp(2.5 * rise, 0, 1) )      спадает до нуля за 0,1 с
level += (raw - level) * ( raw > level ? 1 - exp(-dt / 6 мс) : 1 - exp(-dt / Decay) )

если raw > 0.08:
  dry  += ( 0.6 * attack + 0.4 * |corr| - dry ) * min(1, 6 * dt)       сухость; начальное значение 0,5
  tau   = ( raw > 0.9 * level ) ? 36 мс : 116 мс
  panS  += (pan  - panS)  * ( 1 - exp(-dt / tau) )                     в снимок идут сглаженные panS и corrS
  corrS += (corr - corrS) * ( 1 - exp(-dt / tau) )
```

В снимок полосы (`BandFrame`) уходят level, onset, panS, corrS, dry и peakHz (частота самого сильного бина полосы, km × sr / N; нужна подсказке под курсором). Полоса тише порога держит прежние pan, corr и dry: её форма гаснет на том месте, где звучала.

**Ручка Decay** (затухание) задаёт, как быстро форма пропадает после того, как звук замолчал: от 20 до 600 мс, по умолчанию 90 мс. Нарастание (6 мс) не настраивается. Картинка показывает только то, что звучит сейчас: искусственного продления, следов и шлейфов нет.

**Съём (Rate)** — настройка скорости, а не точности. При каждом съёме восстанавливаются сигналы полос, пересчитывается поле плотности и публикуется `AnalysisFrame`; это самая тяжёлая часть. Между съёмами формы стоят на месте, а камера идёт каждый кадр, поэтому картинка не дёргается. Измерение от Rate не зависит: короткий звук не теряется и расстояние не меняется, какой бы Rate ни был выбран.

**Отличие от прототипа** (решение разработчика). В прототипе измерение шло вместе с картинкой, с частотой Rate и по таймеру браузера. Из-за этого при Rate 20 и ниже между окнами были промежутки (короткий звук мог выпасть), скачок громкости мерился на разном отрезке времени при разном Rate, а два прогона одного звука различались в мелочах. Формулы подобраны при Rate 30. В приложении скачок мерится всегда на отрезке 1/30 с (как в прототипе при Rate 30), сглаживание pan и corr задано временем (36 и 116 мс — это доли 0,6 и 0,25 на съём при Rate 30). При Rate 30 результат должен совпадать с прототипом на глаз; это проверяется на этапе 2 сравнением с прототипом на одном и том же звуке. Если картинка разойдётся, вернуть схему прототипа и спросить пользователя.

**Сухость (dry): откуда берётся расстояние.** Фаза между каналами почти не даёт глубины: у обычной музыки почти всё в фазе, и все звуки оказывались в одном слое (пользователь: «не чувствуется объём»). Поэтому расстояние берётся из того, сухой звук или размытый (выбор пользователя из трёх вариантов: громкость, сухость, оставить фазу). Сухой чёткий звук с резкими атаками стоит близко, размытый без атак далеко. Оценка грубая и собрана из двух измерений: был ли у полосы резкий скачок громкости за последние пару секунд (attack) и насколько каналы совпадают по фазе (|corr|).

**Раскладка в куб** (модуль `visual/SpaceMapping`). Слушатель в центре, в точке (0, 0, 0); ось X вправо (панорама), Y вверх (частота), Z назад (перёд — это −Z). Оси прямые, ничего не заворачивается дугой вокруг слушателя. Единица длины условная: звук лежит в пределах ±1,25. Каждая полоса каждого источника даёт одну объёмную форму:

| Что | Формула | Смысл |
| --- | --- | --- |
| Высота центра | y = −0,85 + 1,7 × b / 31 | Частота: бас внизу, верха наверху |
| Место влево-вправо | x = pan × 0,95 | Панорама |
| Расстояние | z = −(0,55 + 0,7 × (1 − dry)) | Сухой близко (z около −0,55), размытый далеко (z около −1,25) |
| Противофаза | если corr меньше −0,3, знак z меняется на плюс | Звук в явной противофазе стоит сзади, на том же расстоянии |
| Ширина | σx = 0,16 + 0,45 × (1 − \|corr\|) | Звук в фазе узкий, широкий стереозвук растянут по панораме |
| Глубина и высота формы | σz = 0,17; σy = 0,05 | Постоянные |
| Вес | корень из (0,16 / σx) | Широкая форма не становится ярче узкой |

Плотность формы = level^2,4 × 1,3 × вес × (1 + 1,3 × onset). Полоса с level меньше 0,1 пропускается. Форма — гауссов сгусток exp(−(dx²/σx² + dy²/σy² + dz²/σz²) / 2) с этими центром и размерами; считается в пределах ±2,2 σ по каждой оси, вклад меньше 0,004 отбрасывается.

Один источник (дорожка) даёт формы в разных местах сразу: у каждой полосы свои pan, corr и dry. Так барабанная дорожка показывает бочку внизу близко, хэт наверху сбоку, клэп широко.

**Сигнал полосы** (модуль `analysis/BandSignal`). Нити на экране — это настоящие сигналы полос, поэтому при каждом съёме для каждой полосы с raw больше 0,1 восстанавливается кусок её сигнала прямо из её же бинов спектра, без отдельных фильтров:

```text
M[k] = L[k] + R[k]    общее в каналах (mid)        S[k] = L[k] - R[k]    разница каналов (side)

km    = бин полосы с наибольшей энергией |M|^2 + |S|^2
phi   = фаза M[km], а если в этом бине |S| больше |M|, то фаза S[km]
P     = N / km                                     период в отсчётах
span  = min( 4 * P, 900 * N / 2048 )               сколько отсчётов показать: около 4 периодов, у баса меньше
d     = сдвиг от 0 до P, при котором главная составляющая в точке N/4 + d переходит через ноль вверх:
        2*pi*km*(N/4 + d)/N + phi = -pi/2  (по модулю 2*pi);   d не больше max(0, N/2 - span)
start = N/4 + d                                    как запуск развёртки на осциллографе

для j = 0..63:   n = start + j * span / 64
  mid[j]  = sum Re( M[k] * e^(i*2*pi*k*n/N) )      сам сигнал
  quad[j] = sum Im( M[k] * e^(i*2*pi*k*n/N) )      тот же сигнал со сдвигом на четверть периода
  side[j] = sum Re( S[k] * e^(i*2*pi*k*n/N) )
  все три делятся на окно Ханна в точке n (не меньше 0,3), чтобы снять его огибающую
все три нормируются к общему пику, умножаются на min(1, 1.25 * raw) и хранятся целыми -127..127
```

Полоса тише 0,1 не пересчитывается и держит прежний сигнал (её форма всё равно гаснет). Экспонента считается поворотом комплексного числа на постоянный угол от отсчёта к отсчёту, без вызова синуса на каждый отсчёт. Участок всегда лежит в средней половине окна, где окно Ханна не меньше 0,5.

**Поле плотности.** При каждом съёме все формы всех включённых источников складываются в трёхмерную сетку 56 × 40 × 56 (X × Y × Z), которая покрывает объём ±1,45 по X и Z и ±1,1 по Y.

- Плотность копится отдельно по каждому источнику: у источника свой канал, плюс один общий канал с наибольшей плотностью в ячейке (по нему луч пропускает пустоту). На 12 источников это три RGBA-текстуры и одна одноканальная.
- Плотность пишется в 8 бит с множителем 0,6, шейдер делит обратно: так громкие звуки не упираются в потолок и видно, кто из двух сильнее. Ячейка, где наибольшая плотность меньше 0,004, обнуляется.
- Цвет в сетке не хранится: его даёт номер канала, поэтому на границе двух источников цвета не грязнятся.
- Сетка загружается в 3D-текстуры с линейной фильтрацией. Её читают рендер, «тяга к звуку» камеры и подсказка под курсором (по копии в памяти). Размер сетки начальный, зависит от ступени качества (раздел 9).
- Кроме сетки рендеру нужны две маленькие текстуры. Текстура полос, 32 × число источников: level, onset и центр формы (x и z / 1,3, переведённые из −1..1 в 0..255). Текстура сигналов, 64 × (32 × число источников): в строке полосы три канала mid, side, quad.

**Соло и стоп-кадр.** Соло на измерение не влияет: в поле плотности просто не кладутся остальные источники. При стоп-кадре измерение продолжается, но рендер держит последний взятый снимок и поле; после снятия стоп-кадра картинка сразу становится текущей.

**Задержка.** Картинка отстаёт от звука: половина окна (21 мс), шаг измерения и съём (в среднем около 25 мс при Rate 30), отрисовка кадра и буфер входного устройства. В сумме ожидается 60–90 мс без учёта задержки самого экрана или проектора; измерить на этапе 2. На сцене звук идёт в зал аналогом и задержать его нельзя, поэтому это отставание остаётся; в записи оно убирается сдвигом звука (раздел 10).

**Стоимость.** В прототипе (JavaScript) измерение, сигналы полос и поле плотности для пяти дорожек занимали 4–5 мс на съём. Цель для приложения: не больше 8 мс на съём при 12 источниках на машине разработки (раздел 9).

**Темп по звуку.** По низким полосам общего микса главного устройства ищутся удары и оценивается BPM. Это запасной источник темпа для камеры (раздел 12).

**Известные ограничения** (первые два пользователю названы):

- **Сухость ошибается на ровных звуках.** Ровный сухой синтезатор без атак уезжает далеко, как будто он с реверберацией: настоящую реверберацию от просто длинной ноты так не отличить.
- **Бас разбирается грубо.** При окне 2048 и 48 кГц один бин спектра — 23,4 Гц, поэтому четыре нижние полосы (30–66 Гц) собраны всего из двух бинов и повторяют друг друга: одна низкая нота видна несколькими похожими нитями. В показанный участок попадает меньше одного периода самых низких частот, поэтому нити баса почти прямые. Поэтому есть второй вариант, длинное окно для нижних полос (описан сразу под этим списком). Оба варианта стоят за переключателем Bass detail, и пользователь выбирает между ними на своей музыке на этапе 2 (его решение 19 ноября).
- **Смена «спереди — сзади» резкая.** Звук с corr около −0,3 может перескакивать спереди назад и обратно. Если на настоящей музыке это будет заметно, добавить запас: назад при corr ниже −0,35, обратно при corr выше −0,25.

**Длинное окно для низов (переключатель Bass detail).** Off — как в прототипе: всё считается по одному окну N. On — вариант разработчика, нигде не опробованный:

1. Кроме обычного окна считается длинное: N\_low = 4 × N отсчётов (8192 при 48 кГц, один бин 5,9 Гц), окно Ханна, тот же шаг измерения 1/60 с; конец длинного окна совпадает с концом обычного.
2. Для полос 0–9 (30–213 Гц) по длинному окну считаются PL, PR и C с границами бинов по тем же формулам, но с N\_low, и доля полосы: `share(b) = (PL + PR)(b) / сумма (PL + PR) по полосам 0–9`.
3. По обычному окну считается общая мощность низа `P_low`: сумма PL + PR по бинам от `lo(0)` до `hi(9) − 1`, каждый бин один раз.
4. Мощность полосы принимается равной `P_low × share(b)`; дальше dB, raw, level, атака, onset и сухость считаются как обычно. Так бас откликается на удар с той же скоростью, что и остальной звук, а распределение по высоте берётся из длинного окна.
5. Панорама, корреляция, частота пика и сигнал нити для этих полос берутся из длинного окна по тем же правилам, с N\_low вместо N: `span = min(4 × P, 900 × N_low / 2048)`, то есть до четырёх периодов даже у самых низких нот.

Цена варианта On: ещё одно преобразование на источник на каждом шаге (нужно уложиться в бюджет шага измерения из раздела 9) и рисунок нитей баса, который запаздывает за ударом примерно на 60 мс сильнее, чем их яркость. По умолчанию Off, то есть вид прототипа. После выбора пользователя на этапе 2 остаётся один вариант, переключатель убирается.
