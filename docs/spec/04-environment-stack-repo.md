# 4. Окружение, стек, репозиторий

> Часть задания PEJEDED STUDIO, версия 2. Оглавление и список «что читать на каком этапе»: [README.md](README.md). Ссылка «раздел N» в тексте ведёт в файл с номером N.

Сборка и автотесты идут в Docker, готовая программа запускается прямо на машине, версию для macOS собирает GitHub. Машина разработки, по выводу команд пользователя от 19 ноября: ноутбук с Debian 13 «trixie» (13.7, ядро 6.12), встроенная графика AMD Radeon 610M (Mesa 25.0.7, OpenGL 4.6), звук через PipeWire 1.4.2 (48 кГц, блок по умолчанию 1024 отсчёта, наименьший 32). Графика начального уровня, поэтому скорость картинки стала главным риском (раздел 9). Сведения сняты командами `cat /etc/os-release`, `glxinfo -B`, `pw-cli info 0`; они и выводы из них записаны в `docs/environment.md`.

| Часть | Решение | Замечание |
| --- | --- | --- |
| Язык | C++17 |  |
| Сборка | CMake; JUCE подключается как подмодуль git | Версию JUCE зафиксировать тегом (ожидается JUCE 8) |
| Звук, MIDI, окна, декодирование | JUCE (модули audio\_devices, audio\_formats, audio\_utils, dsp, gui\_basics, opengl) | На Linux вход в PipeWire через его JACK-слой; запасной путь ALSA. Проверить задержку обоих путей |
| Графика | OpenGL 3.3 core, шейдеры GLSL 330 | Никаких расширений выше 3.3: старый мак их не даст |
| Видео | Внешний процесс `ffmpeg`, кадры через pipe | Библиотеки FFmpeg не линкуются |
| Растяжение звука (keylock) | Rubber Band или SoundTouch | Выбор на этапе 6: сравнить качество при ±8 % |
| Поиск битов и BPM | Свой модуль или готовая библиотека | За интерфейсом `BeatAnalyzer`, чтобы реализацию можно было заменить |
| Файлы настроек и данных | Настройки и файл сеанса — JSON средствами JUCE; база данных — SQLite, один файл исходника (раздел 16) |  |
| Тесты | Catch2, запуск через `ctest` | Раздел 18 |

**Лицензии.** JUCE распространяется под AGPLv3 или по платной лицензии; Rubber Band — под GPL или по платной лицензии. Репозиторий открытый, поэтому платные лицензии не нужны, если код приложения опубликован под AGPLv3: тогда подходят и JUCE, и Rubber Band. В корне репозитория лежит файл `LICENSE` с текстом AGPLv3. Пользователь подтвердил AGPLv3 19 ноября. Если приложение когда-нибудь станет закрытым, понадобятся платная лицензия JUCE и замена Rubber Band. Лицензию SoundTouch (ожидается LGPL) проверить перед выбором. Это не юридическая консультация.

**Разработка в Docker.** Сборка и автотесты идут в контейнерах. Готовая программа запускается прямо на машине, без контейнера: так между ней и видеокартой, звуком и USB-устройствами нет посредника, задержка звука меньше, а на сцене надёжнее. Компилятор и библиотеки для сборки живут только в образе. Образ один, описан в `Dockerfile` и строится на той же версии Debian, что стоит на машине (Debian 13 «trixie»), чтобы собранная в нём программа запускалась на машине. Каталог проекта подключается в контейнер томом, поэтому исходники и папка `build/` остаются на диске машины. Процессы в контейнере работают от того же пользователя, что на машине, чтобы файлы не становились чужими.

В `compose.yaml` два сервиса на одном образе; обоим нужен только каталог проекта, без экрана, звука и устройств:

| Сервис | Зачем |
| --- | --- |
| `dev` | Сборка и любые команды |
| `test` | Все автотесты одной командой |

На саму машину ставятся Docker и то, что нужно программе для работы, а не для сборки: `ffmpeg` для видеозаписи и системные библиотеки звука и графики, которые на рабочем столе Debian обычно уже есть. Точный список составляется на этапе 1 и записывается в `docs/environment.md`; ставит его пользователь, без его согласия на машину ничего не ставится. Проверить на этапе 1: программа, собранная в контейнере, запускается на машине и видит видеокарту, звук и MIDI.

**Сборка под macOS.** Код один на обе системы, но собрать маковскую версию в Linux-контейнере нельзя, поэтому её собирает GitHub Actions, начиная с этапа 1. При каждом изменении кода собирается программа в формате Universal (один файл для маков на Intel и на Apple Silicon), прогоняются автотесты, готовая программа выкладывается архивом. Пользователю на маке ничего ставить и собирать не нужно: скачать, распаковать, запустить. Описание сборки лежит в `.github/workflows/macos.yml`.

- Сборочные машины GitHub для открытых репозиториев бесплатны, маковские тоже. Репозиторий открытый, поэтому в него не попадают треки, записи, личные настройки, пароли и ключи; это закреплено в `.gitignore`.
- Маковские машины GitHub работают на Apple Silicon. Часть для Intel проверяется там же через Rosetta; проверить, что это работает.
- Самая старая macOS: JUCE 8 допускает запуск начиная с macOS 10.11, но свежий Xcode может не собирать под системы старше 10.13. На старом маке пользователя стоит macOS 12.7.4 Monterey (ответ 19 ноября), поэтому минимальная версия в сборке — macOS 12.0; собирается ли под неё на машинах GitHub, проверяется на этапе 1.
- OpenGL на macOS объявлен устаревшим, но версия 3.3 там есть. Проверить на новом маке (этап 9).
- Автотестам с отрисовкой нужен OpenGL без экрана; есть ли он на маковских машинах GitHub, проверить. Если нет, на маке в GitHub идут модульные тесты и сквозные без картинки.
- Программа не подписана Apple, поэтому первый запуск на маке разрешается вручную в настройках безопасности; пошаговая инструкция пишется в `docs/macos.md`.

Команды сборки и проверки (сборка и тесты в контейнере, запуск на машине):

```text
docker compose build
docker compose run --rm dev cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
docker compose run --rm dev cmake --build build
docker compose run --rm test
./build/PejededStudio
```
